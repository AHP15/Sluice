## D-037: Connection URL parameters are mapped, ignore-listed, or refused

- **Status**: superseded
- **Date**: 2026-11-07
- **Date superseded**: 2026-11-07
- **Date deprecated**:
- **Date promoted**:
- **Context**: The launcher (`src-tauri/src/launcher.rs`) maps user, host,
  database and TLS parameters from a connection URL and silently drops every
  other parameter for every engine, so `?replicaSet=rs0` vanishes without
  trace. The profile file already treats unknown keys as errors because
  ignoring one "would quietly connect somewhere else".
- **Decision**: Every connection URL parameter falls into one of three
  classes per engine. **Mapped**: user, host, database, TLS, and the D-033
  typed options — applied. **Ignore-listed**: a short per-engine allow-list of
  parameters whose absence provably cannot change where Sluice connects, who
  it authenticates as, or how strongly TLS is verified (e.g. Mongo
  `retryWrites`, `w`, `appName`; Postgres `application_name`,
  `connect_timeout`) — dropped, but listed in a visible notice. **Everything
  else** — refused, naming the parameter. This holds wherever a URL enters:
  CLI launch, pasted URLs, and URLs from evaluated config files (D-026).
- **Rationale**: Refusing everything unmapped would break copy-paste of the
  URLs hosted providers hand out, which nearly always carry `retryWrites`,
  `w=majority` or `sslmode`. Silent dropping is the failure being removed.
  The cost is a per-engine list that must be reviewed whenever it grows.
- **Superseded by**: D-041
