## D-040: Engine-neutral connection address, with discovery confined to seed lists and SRV

- **Status**: accepted
- **Date**: 2026-11-07
- **Date superseded**:
- **Date deprecated**:
- **Date promoted**:
- **Context**: D-034 introduced an engine-neutral `Address` (`Host`, `Seeds`,
  `Srv`), but red-teaming found two failures it licensed. Topology discovery
  replaces a configured `localhost` seed with the members' advertised
  hostnames, so it connects around the `ssh -L` tunnel D-008 documents
  (R-044); and the production guardrails (`production_reasons` in
  `src-tauri/src/guardrails.rs`) evaluate one host string, not the members
  actually connected (R-045).
- **Decision**: `Target` carries `address: Address` with variants
  `Host { host, port }`, `Seeds(Vec<HostPort>)` and `Srv { name }`; every
  driver matches on it and refuses an unsupported form by name (today Postgres
  and SQL Server accept only `Host`, Mongo all three). The profile file keeps
  `host` / `port` for `Host` and adds mutually exclusive `hosts = [..]` and
  `srv = ".."`. **A `Host` address always connects directly** to that one
  server — no topology discovery, even when engine options name a replica
  set (the set name is then only verified). Discovery happens only for
  `Seeds` and `Srv`, and when it yields a member outside the configured seeds
  while any seed is loopback, the connection is refused with an explanation
  that discovery would bypass a tunnel and a pointer to a `Host` profile per
  member. **Guardrails are evaluated over every configured and every
  discovered member**, armed if any member would arm them, and re-evaluated
  whenever the driver reports a topology change. Displays use a rendered form
  (`srv:cluster0.example.net`, `h1:27017, h2:27017 (+1)`); keychain identity
  stays the profile `id`.
- **Rationale**: Keeping single-host profiles direct preserves the one
  routing guarantee the documented tunnel workaround depends on, while seed
  lists and SRV — which exist to be discovered — still get discovery.
  Evaluating guardrails over the members actually connected makes D-027's
  production confirmation describe the servers that will receive the writes,
  not a label.
- **Supersedes**: D-034
