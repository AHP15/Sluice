## D-023: UI stack: TanStack grid, CodeMirror 6, Tailwind/shadcn

- **Status**: accepted
- **Date**: 2026-07-30
- **Context**: The UI must feel "fancy" and feature-rich while running inside
  the OS webview, whose floor is WebKitGTK (D-019), and must virtualize
  arbitrarily long result sets (D-010). Recorded as a tentative default rather
  than a hard-fought decision, since it is reversible.
- **Decision**: TanStack Table (headless) with TanStack Virtual for the grid;
  CodeMirror 6 rather than Monaco for the query editor; Tailwind with
  shadcn/ui for styling; TanStack Query for IPC-backed data with Zustand for
  local UI state; Vite as the dev server, driven by Bun per D-001. Target
  WebKitGTK's CSS support -- no subgrid and no bleeding-edge features.
- **Rationale**: Virtualization is mandatory under D-010, so a headless table
  paired with a virtualizer beats a monolithic grid with licensing tiers.
  CodeMirror 6 is far lighter than Monaco and its worker model behaves in a
  Tauri asset context, where Monaco's is awkward. Targeting the WebKitGTK floor
  avoids the classic failure of discovering a broken grid on Linux late.
  Tentative: revisit once the grid is real.
