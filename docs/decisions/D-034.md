## D-034: Engine-neutral connection address: host, seed list, or SRV

- **Status**: superseded
- **Date**: 2026-11-07
- **Date superseded**: 2026-11-07
- **Date deprecated**:
- **Date promoted**:
- **Context**: A Mongo deployment is addressed by one host, a seed list of
  members, or an SRV name that resolves to members; the current `Target`
  models only one host and port. Multi-host addressing is not Mongo-only —
  libpq accepts several hosts for failover and SQL Server has a failover
  partner — and an SRV name has no port, so a host/port pair plus flags would
  allow meaningless states.
- **Decision**: `Target` carries `address: Address` with variants
  `Host { host, port }`, `Seeds(Vec<HostPort>)` and `Srv { name }`. Every
  driver matches on it and refuses a form it does not support by name, the
  D-008 pattern for unbuilt transport variants; today Postgres and SQL Server
  accept only `Host`, Mongo accepts all three. The profile file keeps `host` /
  `port` for the single-host case and adds mutually exclusive `hosts = [..]`
  and `srv = ".."`; more than one is an error. Displays (UI labels, history)
  use a rendered form such as `srv:cluster0.example.net` or
  `h1:27017, h2:27017 (+1)`. Keychain identity stays the profile `id`.
- **Rationale**: Putting SRV and seed lists in Mongo's options would make the
  next engine needing failover reinvent them, and would leave `port` silently
  ignored under SRV. A typed address makes the invalid combinations
  unrepresentable, at the one-time cost of a display form wherever
  `target.host` is read today.
