## D-001: Rust core owns all database connections

- **Status**: accepted
- **Date**: 2026-07-30
- **Context**: The product is specified as Bun + React + Tauri, but Tauri's
  core is a Rust process and Bun is a separate JS runtime, so only one of them
  can own the database sockets. The choice determines binary size,
  cross-compilation difficulty, driver availability, and whether cancellation
  and streaming are native primitives or hand-rolled across a process boundary.
- **Decision**: The Tauri Rust process owns every database connection. Bun is
  demoted to build tooling only (package manager, dev server / bundler driver
  for the React app) and is not shipped in the artifact. No Bun sidecar.
- **Rationale**: All three launch engines have mature pure-Rust drivers, so
  there is no C toolchain and cross-compilation stays boring; the binary is
  roughly 15MB rather than the 60-100MB a per-platform Bun sidecar costs; and
  query cancellation, backpressured streaming, and pooling come from tokio
  instead of being reinvented over stdio. A Bun sidecar's main draw is the npm
  driver ecosystem, but its weakest point is SQL Server, where `tedious` leans
  on Node net/tls/crypto edge cases that have historically been flaky under
  Bun -- betting the second engine on unowned runtime compatibility. The
  long-tail "every database" ambition is served by an out-of-process plugin
  boundary (D-003), which can host a Bun driver later regardless of core
  language.
