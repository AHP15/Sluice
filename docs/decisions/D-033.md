## D-033: Typed, closed per-engine connection options

- **Status**: superseded
- **Date**: 2026-11-07
- **Date superseded**: 2026-11-07
- **Date deprecated**:
- **Date promoted**:
- **Context**: The engine-neutral connection target (`Target` in
  `src-tauri/src/engines.rs`, read during T-087) carries only host, port,
  user, database, TLS, timeout and budget, so Mongo's `replicaSet` and
  `authSource` have nowhere to live and `mongodb+srv` / replica-set URLs fail.
  Any carrier for engine options must not let a profile or URL override what
  D-007, D-027 and D-028 guarantee, and must fit D-011's hand-editable profile
  file, where unknown keys are already errors.
- **Decision**: `Target` gains `options: EngineOptions`, an enum with one
  closed, typed variant per engine (`Postgres{..}`, `Sqlserver{..}`,
  `Mongodb{ replica_set, auth_source, .. }`); each driver receives only its own
  variant. In the profile file the options are a closed `[profile.<engine>]`
  sub-table whose unknown keys are errors, validated at load time like the rest
  of the file. Settings that would override a settled guarantee are
  deliberately never options: pool size (D-028), TLS weakening beyond the
  existing `tls` key and its URL mapping (D-007/T-021), `directConnection`,
  and `readPreference` (writes and the budget assume the primary). Options are
  non-secret and may be logged in shape per D-020.
- **Rationale**: A free-form passthrough map would let any URL or hand edit
  silently break the budget, the TLS default, or which server receives writes,
  and every driver would have to re-police every key. Storing the URL itself
  as the address duplicates host/port/tls and invites the password back into a
  file D-011 promises is safe to commit. Typed options cost a struct per engine
  but make "what can this profile change?" a checkable answer.
- **Superseded by**: D-042
