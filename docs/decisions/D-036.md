## D-036: Mongo authSource is an option; the auth mechanism follows the credential provider

- **Status**: accepted
- **Date**: 2026-11-07
- **Date superseded**:
- **Date deprecated**:
- **Date promoted**:
- **Context**: The T-087 driver authenticates against the profile's
  database, which fails on Atlas, where users are defined in `admin`. Mongo
  URLs also carry `authMechanism` (SCRAM, X.509, AWS, OIDC, GSSAPI, PLAIN),
  but D-008 already models where a credential comes from as a provider
  (`static | keychain | env | iam-token`), and the mechanism determines what
  kind of credential is needed.
- **Decision**: `auth_source` is a typed Mongo option (D-033). Unset, it
  follows Mongo's own URI rule as `mongosh` does: the connection's named
  database if any, else `admin`. Precedence is explicit option, then an SRV
  TXT record (D-039), then that default. The auth mechanism is not an option:
  the D-008 provider decides it. Password providers (`keychain`, `env`,
  `static`) mean SCRAM, version negotiated. X.509, AWS IAM, OIDC, GSSAPI and
  PLAIN become providers when built; until then a URL naming one is refused by
  name with a workaround, never silently downgraded to a password. The same
  rule governs SQL Server's Entra and Kerberos modes (T-072).
- **Rationale**: Following Mongo's rule means a URL pasted from Atlas or
  `mongosh` behaves as it does in every other client; a Sluice-specific
  default would break either Atlas or self-hosted app-database users. A
  mechanism option independent of the provider would let a profile claim
  X.509 while the keychain supplies a password — the mismatch D-008 exists to
  prevent.
