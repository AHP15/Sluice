## D-038: Profile file format version 2, written only when needed

- **Status**: accepted
- **Date**: 2026-11-07
- **Date superseded**:
- **Date deprecated**:
- **Date promoted**:
- **Context**: D-033 and D-034 add profile keys (`hosts`, `srv`,
  `[profile.<engine>]`). Older builds refuse unknown keys, naming the key, and
  refuse — and will not save over — a file with a newer `version`
  (`docs/PROFILE-FILE.md`). A second machine on an older build must fail in
  a way that tells the user what to do.
- **Decision**: Format version 2 defines the new keys. The writer emits the
  lowest version that can express the file: a file using none of the new keys
  stays `version = 1` and readable by older builds; once any profile uses a
  non-`Host` address or engine options, the file is written as `version = 2`,
  and older builds meet the existing "newer version — update to edit"
  refusal rather than an unknown-key error.
- **Rationale**: Always writing version 2 would lock older builds out of
  files that use nothing new; never bumping relies on an unknown-key error
  that names a key but not the remedy. Writing the lowest sufficient version
  keeps compatibility wherever it is free and a clear refusal where it is
  not.
