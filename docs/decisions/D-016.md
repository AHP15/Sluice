## D-016: Native catalog introspection with version and flavour gating

- **Status**: accepted
- **Date**: 2026-07-30
- **Context**: Schema introspection must serve a navigator tree over databases
  that may contain ten thousand tables, across engine versions spanning many
  years, and against wire-compatible-but-not-catalog-compatible forks.
- **Decision**: Query native catalogs (`pg_catalog`, `sys.*`,
  `listCollections`/`listIndexes`), not `information_schema`. At connect,
  detect server version *and flavour* by parsing `version()`, and put both in
  the connection's capability descriptor, gating catalog queries and features
  on them. Load the tree lazily level-by-level -- schemas up front, tables on
  schema expand, columns and indexes on table select -- into an in-memory cache
  per connection with an explicit refresh action. Invalidate automatically
  after DDL the app itself executed. Missing catalog rows and permission-denied
  on catalog views are normal conditions to render around, not connection
  failures.
- **Rationale**: `information_schema`'s portability advantage is illusory since
  per-driver code exists anyway, while it is slower (permission-filtered views
  over the catalogs) and cannot express partitioning, index methods,
  materialized views, or exclusion constraints. Flavour detection is the step
  usually skipped: a Postgres driver will be pointed at CockroachDB, Redshift,
  Timescale, Yugabyte, or a transaction-mode PgBouncer, none of which are
  catalog-compatible, and the alternative is a client that half-works and
  blames the user. Lazy loading is what keeps a 10k-table database usable;
  eager introspection makes connect take thirty seconds. External DDL is
  undetectable without polling, so refresh is the contract, not a fallback.
