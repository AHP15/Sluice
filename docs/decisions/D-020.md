## D-020: Shape-only logging with type-enforced redaction

- **Status**: accepted
- **Date**: 2026-07-30
- **Context**: D-011 ruled out telemetry, so logs are purely local -- and in a
  database client they are the highest-risk artifact the app produces, since
  the natural log line is a query and its parameters, containing exactly the
  sensitive data the user was working with.
- **Decision**: Structured logging via `tracing`. Default content policy is
  shape-only: statement kind, duration, row count, error kind, profile id --
  never parameter values or result rows. Full query text sits behind a clearly
  labelled "verbose diagnostics" toggle that is session-scoped and off by
  default. Wrap secrets in a `Secret<String>` whose `Debug` and `Display`
  print `[redacted]`. Rotating file logs in the cache dir with a size cap. On
  panic, write a local crash file with backtrace and offer a "copy
  diagnostics" action that shows the user exactly what will be copied. Nothing
  is ever uploaded and logs are never auto-attached.
- **Rationale**: Logging everything locally gives the best debugging and makes
  the log the most sensitive file on disk, readable by anything running as the
  user and easy to paste into an issue by accident. Minimal logging makes
  intermittent driver and performance bugs very hard to diagnose. Type-level
  redaction makes password leaks impossible rather than remembered at every
  call site, closing the same hole D-017 closes at the boundary. Side benefit:
  `tracing` spans around the query lifecycle supply the UI's per-query timing
  display for free.
