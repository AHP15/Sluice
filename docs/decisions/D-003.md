## D-003: In-tree wire-shaped Driver trait with declared capabilities

- **Status**: accepted
- **Date**: 2026-07-30
- **Context**: "Support every database ever" implies drivers this project will
  not author, but building a third-party plugin SDK before Postgres works is
  the reliable way to never ship. The scope is a personal tool that should stay
  extensible later (see D-011).
- **Decision**: Define a compiled-in Rust `Driver` trait whose methods take and
  return plain owned data only -- no lifetimes, no engine handles, nothing
  opaque escaping into the interface -- so the same shape can be lifted onto a
  wire protocol later without redesign. Every behavioural difference between
  engines is expressed as declared capability data, never as engine checks in
  the React layer. Wrap every IPC command boundary in `catch_unwind` and never
  configure `panic = "abort"`.
- **Rationale**: The trait is easy; the leak-proofing is the actual work and
  the thing that buys extensibility. An out-of-process protocol now would cost
  versioning, discovery, handshake, and subprocess supervision while collecting
  no benefit from a single author. WASM is unusable because WASI sockets are
  immature, so a WASM driver cannot open its own connection; `cdylib` plugins
  are unusable because Rust has no stable ABI. Known consequence on the record:
  in-process drivers mean a driver panic can take down the whole window, which
  out-of-process plugins would have isolated for free.
