## D-002: Use low-level driver crates, not sqlx

- **Status**: accepted
- **Date**: 2026-07-30
- **Context**: With the core in Rust (D-001), the driver layer is either sqlx
  or the engine-specific crates. A database *client* has the inverse
  requirements of an application ORM: schemas are unknown at compile time and
  every column type must render faithfully, including types no Rust mapping
  exists for.
- **Decision**: Use `tokio-postgres`, `tiberius`, and the official `mongodb`
  crate directly. Connection pooling via `bb8` or `deadpool`. Do not use sqlx,
  including its `Any` driver.
- **Rationale**: sqlx exists to verify queries against a known schema and map
  columns into known Rust types, and will either refuse or lossily coerce
  PostGIS geometry, `tsvector`, custom enums, domains, and arrays of
  composites. `tokio-postgres` exposes the raw row plus type OID, which is
  exactly the input D-006's tagged encoding needs. Independently, sqlx dropped
  its MSSQL driver in 0.7 and has not restored it, so SQL Server needs
  `tiberius` regardless -- choosing sqlx would mean maintaining two driver
  idioms for no gain. Cost accepted: pooling is hand-managed rather than free.
