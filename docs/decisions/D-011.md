## D-011: Local-only single user with a portable profile file

- **Status**: accepted
- **Date**: 2026-07-30
- **Context**: "Single-tenant, local, one user" was an unstated premise. The
  opposite answer would require a server, identity, per-user permissions, and
  audit logging, and would make the credential model an entirely different
  problem -- so it must be ratified rather than assumed.
- **Decision**: Local-only. No accounts, no server, no cloud sync, no
  telemetry. Profiles and saved queries live in a plain, documented,
  human-editable file that is safe to commit to git or sync via a file-sharing
  folder. Team collaboration, shared profiles, and hosted variants are explicit
  non-goals.
- **Rationale**: Because credentials live in the keychain and never in the
  config file (D-007), that file is safe to sync -- which delivers most of the
  practical value of "share connection profiles with my team" for none of the
  backend, auth, or hosting cost. Deciding it now matters because the
  multi-user answer changes nearly every decision above it. Note the
  portability commitment covers profiles and saved queries specifically, not
  query history or tab state (see D-014).
