## D-024: Export formats: CSV, JSONL, SQL INSERT, streamed to file

- **Status**: accepted
- **Date**: 2026-07-30
- **Context**: D-010 caps raw-query results and offers "export the full result
  to a file" as the escape hatch for large sets, so the export subsystem is a
  required counterpart -- but post-v1 per D-022. Recorded as a tentative
  default.
- **Decision**: Export CSV, JSONL, and SQL `INSERT` statements, streamed
  directly to disk without materialising in the webview, using D-006's
  lossless string representations for every value. Wire it to D-010's
  truncation notice as the offered next action. Deferred to post-v1.
- **Rationale**: Those three formats cover spreadsheet handoff, pipeline
  ingestion, and reseeding another database, which is nearly all real use.
  Streaming rather than buffering is what makes the escape hatch meaningful for
  results too large for the UI. Using D-006's string forms means exports do not
  reintroduce the precision loss the wire encoding was designed to prevent.
