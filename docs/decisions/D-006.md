## D-006: Lossless wire values via column type descriptors

- **Status**: accepted
- **Date**: 2026-07-30
- **Context**: The default IPC encoding between the Rust core and the webview
  is JSON, whose numbers are f64. Postgres `int8`/`numeric`/`timestamptz`,
  Mongo `Decimal128`/`ObjectId`/`Long`, and SQL Server `datetime2`/`money` do
  not survive that round-trip. Whatever encoding is chosen becomes
  near-unchangeable once features build on it.
- **Decision**: Send a per-column type descriptor once with each result set and
  keep cells lean. Governing rule: the core never hands the UI a value in a
  form JavaScript would silently damage -- when in doubt, string plus type tag.
  Large integers, arbitrary-precision decimals, all temporal types (preserving
  offset and sub-millisecond precision), binary as base64, uuid, and exotic
  types like geometry and `tsvector` all cross as tagged strings; only
  booleans, small integers, and f64-native floats go raw. Model three cell
  states -- present value, SQL NULL, and field-absent. Retain the original wire
  value alongside any edit. Keep the descriptor transport-agnostic.
- **Rationale**: Putting the type on the descriptor rather than every cell
  makes fidelity almost free per row. Drizzle Studio's "everything is a display
  string" is lossless for viewing but erases the difference between `"123"` and
  `123`, blocking typed editing, correct client-side sort, and safe write-back.
  Binary encodings (Arrow, msgpack) are a later transport optimisation, not an
  alternative, since exotic types still need the tag layer. The value/NULL/absent
  distinction is Mongo-critical: conflating null with absent makes edits
  silently create fields.
