## D-012: Context-aware GUI launcher with reserved subcommands

- **Status**: accepted
- **Date**: 2026-07-30
- **Context**: The ask was "an exe I can run from the CLI". Tauri produces a
  `.app` bundle on macOS whose executable sits under `Contents/MacOS/`, so a
  `dbc` on PATH needs a shim or Homebrew formula -- an install step, not a
  build output. Windows and Linux do produce the single-file behaviour
  described.
- **Decision**: Invoking the binary opens the GUI, discovering connection
  details from the working directory -- `DATABASE_URL`, `.env`, and optionally
  drizzle/Prisma config -- and connecting immediately. Explicit forms `dbc
  <url>` and `dbc --profile <name>` are supported. Argument grammar is fixed
  now: subcommands are reserved words, and a bare argument is a connection URL
  if it parses as one, otherwise a directory path. Run as a single instance via
  Tauri's single-instance plugin; a second invocation opens a new tab in the
  existing window and focuses it. Headless subcommands (`dbc query`, `dbc
  dump`) are deferred but their namespace is reserved.
- **Rationale**: `cd project && dbc` is the genuinely excellent part of
  `drizzle-kit studio` and what makes a tool feel native to a dev workflow.
  Fixing the argument grammar now keeps `dbc query "select 1"` available later
  without breaking `dbc postgres://...`. Without single-instance, invoking in
  three project directories gives three processes, three pools, and three
  keychain prompts. A full dual-mode CLI in v1 would roughly double surface
  area, since every feature needs a terminal output design.
