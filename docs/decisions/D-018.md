## D-018: Column derivation for schemaless collections

- **Status**: accepted
- **Date**: 2026-07-30
- **Context**: Mongo collections have no declared schema, so before a grid can
  render anything the product must decide what a column is. This generalises to
  any future document or key-value engine.
- **Decision**: Use the collection's `$jsonSchema` validator when one exists;
  otherwise infer paths from a bounded sample (cheap `find().limit(N)` in
  natural order by default, deeper `$sample` on request), presenting the union
  of observed paths ordered by frequency with a visible marker on paths whose
  type varies. A raw document view is always available as an alternate renderer
  over the same result. Inference is presentation-only: it must never reject,
  coerce, or hide a value. Arrays are a single cell, never flattened into rows.
  Users can pin, hide, reorder, and manually add paths; inference is cached per
  collection and explicitly refreshable. Expose this as a declared driver
  capability rather than Mongo-specific code.
- **Rationale**: A validator is authoritative and cheaper than sampling when
  present, so ignoring it would be wasteful. Presentation-only inference is
  what keeps documents that do not match the inferred shape fully viewable and
  editable -- otherwise the tool starts lying about the data. Flattening arrays
  into rows changes result cardinality and destroys the one-row-one-document
  identity that D-009's editing model depends on, so drill-in belongs in the
  document view. `$sample` on a very large collection is not free.
