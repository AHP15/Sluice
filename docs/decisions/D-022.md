## D-022: MVP feature floor and Postgres -> SQL Server -> Mongo sequencing

- **Status**: accepted
- **Date**: 2026-07-30
- **Context**: The stated ambition is Drizzle Studio parity or beyond across
  three engines, which is far too much for a first release. Both the feature
  floor and the engine order need fixing, and the order determines when the
  cross-paradigm contract (D-004) gets validated.
- **Decision**: v1 ships connect (profile, URL, or cwd discovery), the
  navigator tree, the browse grid with filtering/sorting/keyset pagination, the
  raw query editor with working cancellation, staged edits with statement
  preview, and good error surfacing. Explicitly out of v1: export, ERD
  diagrams, migrations, autocomplete, EXPLAIN visualisation, AI assistance.
  Engine order is Postgres, then SQL Server, then MongoDB. Mitigation attached:
  write Mongo's capability descriptor and a stub driver early as a design-only
  conformance check, so D-004's contract is validated on paper before two
  relational engines calcify around it.
- **Rationale**: The feature floor falls out of the prior decisions rather than
  being chosen freshly. On ordering, the design-optimal choice would be Mongo
  second -- the project's abstraction risk is not SQL dialect variation but
  whether the generic tree, browse contract, type classes, and D-018 inference
  survive a document store, and that is cheapest to discover early. The
  owner chose SQL Server second because it is the engine needed day-to-day, and
  a tool usable on Monday outweighs optimal sequencing. The Mongo stub check is
  the cheap substitute for the validation that ordering defers.
