## D-041: Connection URL parameters are mapped, honoured as behaviour, ignore-listed, or refused

- **Status**: accepted
- **Date**: 2026-11-07
- **Date superseded**:
- **Date deprecated**:
- **Date promoted**:
- **Context**: D-037 sorted URL parameters into mapped, ignore-listed and
  refused, with "ignorable" meaning dropping it cannot change where Sluice
  connects, who it authenticates as, or how strongly TLS is verified.
  Red-teaming found that criterion too narrow: DocumentDB and Cosmos DB need
  `retryWrites=false` or every write fails (R-050), and the Prisma URLs most
  projects carry (`schema`, `connection_limit`, `pgbouncer`, `sslaccept`)
  would be refused where they launch today (R-049) — and `pgbouncer=true`
  cannot simply be ignored, since PgBouncer's transaction mode breaks named
  prepared statements.
- **Decision**: Every connection URL parameter falls into one of four
  classes per engine. **Mapped**: user, host, database, TLS settings (D-042)
  and the typed engine options — applied. **Behaviour flags**: parameters
  whose absence would make operations fail — e.g. Mongo `retryWrites=false`,
  Postgres `pgbouncer=true` (unnamed statements only) — honoured as a
  declared driver behaviour. **Ignore-listed**: a short per-engine list of
  parameters whose absence provably cannot change where Sluice connects, who
  it authenticates as, how strongly TLS is verified, **or whether operations
  succeed** (e.g. Mongo `w`, `appName`; Postgres `application_name`,
  `connect_timeout`; Prisma's `schema` and `connection_limit`) — dropped, but
  listed in a visible notice. **Everything else** — refused, naming the
  parameter. This holds for CLI launch, pasted URLs and URLs from evaluated
  config files (D-026).
- **Rationale**: Copy-paste of the URLs providers and ORMs hand out must keep
  working, and silent dropping must end; both require a list, but the list's
  admission test has to include "operations still succeed", because a
  parameter can be routing-neutral and still be load-bearing. Honouring the
  few such flags is cheaper than refusing the stock URLs of whole hosting
  platforms.
