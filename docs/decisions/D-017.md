## D-017: Layered error model: kind, hints, verbatim payload

- **Status**: accepted
- **Date**: 2026-07-30
- **Context**: Errors largely determine whether a database client feels good or
  hostile, and engine errors are wildly heterogeneous -- SQLSTATE plus detail,
  hint, and position for Postgres; number, severity, and line for SQL Server;
  code and `codeName` plus per-document write errors for Mongo.
- **Decision**: Three layers. A small normalized `kind` enum (connection
  failed, auth failed, timeout, cancelled, syntax error, constraint violation,
  permission denied, not found, conflict, driver bug, unknown -- with `unknown`
  first-class). Optional structured hints: query position, constraint and
  column name, `retryable`. And the engine's raw payload always preserved
  verbatim. Convert Postgres' byte-offset error position to a character index
  at the driver boundary. `cancelled` is a distinct kind, not a failure.
  Redact credentials before an error leaves the core. Model partial failure
  per-statement and per-document rather than collapsing to one global error.
- **Rationale**: Raw passthrough blocks syntax highlighting, constraint-aware
  recovery, and retry logic; a fully closed taxonomy demands endless per-engine
  mapping and still loses detail the user needed. `unknown` means drivers never
  have to lie. An unconverted byte offset highlights the wrong character in any
  query containing non-ASCII text. A user-initiated cancel surfacing as a red
  error makes the app feel broken every time someone stops a slow query.
  Connection failures routinely embed the full connection string including the
  password, so unredacted errors defeat D-007 in the most mundane way possible.
