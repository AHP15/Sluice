## D-035: Driver monitoring connections are declared overhead outside the budget

- **Status**: accepted
- **Date**: 2026-11-07
- **Date superseded**:
- **Date deprecated**:
- **Date promoted**:
- **Context**: D-028 puts every connection a profile opens under one
  per-profile budget. On a replica set the official `mongodb` crate applies
  `max_pool_size` per server and keeps one monitoring socket per member
  outside its pool (reported by the T-087 worker), so the true count is the
  budget plus one per member. This qualifies D-028; it does not supersede it.
- **Decision**: The D-028 budget counts application connections — pooled
  plus pinned. Because `readPreference` is fixed to the primary (D-033), only
  one server's pool is ever used, so application connections never exceed the
  budget. Topology-monitoring sockets a driver cannot avoid are declared
  overhead: the driver reports their count (one per known member) in pool
  stats, and the connection-usage UI shows them separately from the budget.
  Overhead is never hidden and never carries queries.
- **Rationale**: Shrinking the pool to fit monitors inside the budget makes a
  budget of 3 on a three-member replica set unusable, while the monitors are
  idle heartbeat sockets that do not threaten the server's connection limit
  the budget exists to protect. Declaring them keeps the budget honest without
  making small budgets unusable.
