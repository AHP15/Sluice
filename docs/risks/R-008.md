## R-008: Large binary and text values base64-encoded into one payload can kill the webview

- **Severity**: high
- **Likelihood**: medium
- **Disposition**: mitigate
- **Date**: 2026-07-31
- **Description**: Binary values cross as base64, which inflates them by a third, and the encoding is applied per value with no size ceiling. Browsing a table with a 50MB `bytea` — a stored PDF, an image, a backup blob — produces a ~67MB string inside a JSON payload that must be serialized in Rust, parsed in the webview, and held in a grid cell. A single row can take the app down, and browsing such a table is a normal action with no warning attached.
- **Disposition rationale**: High severity at medium likelihood, and browsing a table that happens to contain a blob is a normal action with no warning attached — so the guard has to sit in the encoding path, not in user caution.
- **Action**: Guard: a per-value size ceiling in the wire encoder (default in the low hundreds of KB). Values above it cross as a placeholder descriptor — type, exact byte length, opaque handle — and the grid renders the size plus `load value` / `save to file` actions that stream the full value on demand rather than inline. Applies to `text` and `json` as well as binary, since a 50MB text column is the same failure without the base64 inflation. Mitigating tasks: T-018.
- **Related decisions**: D-006, D-010
