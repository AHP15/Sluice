## R-052: Fixing reads to the primary forbids browsing a secondary or a replica set with no primary

- **Severity**: low
- **Likelihood**: medium
- **Disposition**: accept
- **Date**: 2026-11-07
- **Date resolved**:
- **Description**: D-033 makes `readPreference` a non-option so writes and the budget assume the primary. That also forbids a common safe practice — pointing an exploration tool at a secondary or Atlas analytics node so ad-hoc queries cannot load the primary — and makes a discovered replica set entirely unbrowsable during an election or in a disaster-recovery site with no primary, even though the data is readable. Users then fall back to a single-host `direct` profile to a secondary, which loses discovery and reintroduces the unguarded paths above.
- **Disposition rationale**: Low severity at medium likelihood; under D-040 a single-host `direct` profile to a secondary still works and is guardrailed, which covers exploration of secondaries and analytics nodes.
- **Action**: none — a `Host` profile per secondary is the supported path; revisit only if read-preference becomes a requested option.
- **Related decisions**: D-033, D-035
