## R-053: One version-2 profile makes the whole synced file unreadable on an older build

- **Severity**: medium
- **Likelihood**: medium
- **Disposition**: mitigate
- **Date**: 2026-11-07
- **Date resolved**:
- **Description**: D-038 bumps the file to version 2 as soon as any one profile uses a non-`Host` address or engine options, and an older build refuses a newer-version file wholesale. D-011 positions the file as something to sync via git or a shared folder across machines; adding a single SRV profile on a laptop that updated first leaves every Postgres and SQL Server profile unusable on the machine that has not, rather than only the profile that needs the new keys.
- **Disposition rationale**: Medium severity at medium likelihood; D-038's version rule is sound, but the user must see the cost before paying it.
- **Action**: Guard: before the first save that would raise the file to version 2, the app warns that machines on older builds will refuse the whole file and names the minimum version; the version-refusal message on older builds names the version required. Applies from the first build that can write version 2. Mitigating tasks: T-101.
- **Related decisions**: D-038, D-011
