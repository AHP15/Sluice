## R-020: The single columns-and-rows result shape cannot express DDL, affected rows, or multiple result sets

- **Severity**: high
- **Likelihood**: high
- **Disposition**: fix
- **Date**: 2026-07-31
- **Description**: Every driver method returns columns-plus-rows, but a SQL editor's normal output includes statements with no result set (`CREATE TABLE`), statements whose result is a count (`UPDATE ... 47 rows affected`), multi-statement scripts producing several result sets in sequence, and Mongo commands returning a single status document. Forcing these into one rows-shaped envelope either fabricates empty tables or requires an out-of-band channel the contract does not define — and multi-statement scripts are core to the query editor being shipped in v1.
- **Disposition rationale**: High severity and high likelihood: multi-statement scripts and DDL are ordinary query-editor output, so the gap is hit immediately, not eventually — and the wire shape is the most expensive artifact in the design to change once two engines build on it. The constraint is stated in the decision, so it can only be resolved by changing it.
- **Action**: Superseded by D-029 — every execution now returns an ordered sequence of statement outcomes (`rows` | `affected` | `status` | `error`), each carrying its source statement's text span, making DDL, affected counts, multi-result scripts, and Mongo command documents first-class and reaching D-017's per-statement partial-failure model. Structured browse yields a one-element sequence, so the grid path is unchanged. D-004 -> superseded.
- **Related decisions**: D-004, D-017, D-022
