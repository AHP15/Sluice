## R-006: Tauri IPC offers no backpressure, so streamed batches can exhaust webview memory

- **Severity**: high
- **Likelihood**: medium
- **Disposition**: mitigate
- **Date**: 2026-07-31
- **Description**: The design calls for backpressured streaming of row batches, but Tauri's channel and event mechanisms are fire-and-forget — the Rust side can emit faster than React can consume and render. A fast local Postgres streaming a large table will queue batches in the webview faster than the virtualized grid retires them, growing memory without bound until the webview is killed. Backpressure has to be built as an explicit application-level protocol; it is not a property of the transport.
- **Disposition rationale**: High severity — an unbounded queue takes the webview down — at medium likelihood. D-010 assumed backpressure rather than specifying it, so the guard is simply to build the protocol the decision already intended.
- **Action**: Guard: an explicit credit-based protocol at the application level — the webview acknowledges each batch and the core emits the next only against outstanding credit, with a small fixed number of in-flight batches and a bounded ring of retained rows. The virtualized grid retiring rows is what returns credit, so producer rate is bound to render rate by construction rather than by hoping the transport pushes back. Cancellation and the statement timeout stay reachable while the stream is blocked on credit. Mitigating tasks: T-049.
- **Related decisions**: D-010, D-004
