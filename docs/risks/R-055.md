## R-055: A single seed with `replicaSet` stops meaning discovery, so the most common replica-set URL loses failover

- **Severity**: medium
- **Likelihood**: high
- **Disposition**: mitigate
- **Date**: 2026-11-07
- **Date resolved**:
- **Description**: In the Mongo URI spec, `mongodb://db1:27017/app?replicaSet=rs0` means "discover the set from this seed"; it is how most self-hosted deployments and many tutorials write their connection string, and `mongosh` fails over with it. D-040 makes any `Host` address connect directly, verifying the set name only, so the same URL in Sluice pins one member: after a step-down or maintenance failover every write fails with `NotWritablePrimary` until the user rewrites the profile as a seed list. It also quietly breaks D-036's premise that pasted URLs behave as in `mongosh`.
- **Disposition rationale**: Medium severity at high likelihood, but D-040 already has the right shape for it: a one-element seed list is a `Seeds` address and gets discovery, so the guard is in how URLs and profiles map onto it, not in the decision.
- **Action**: Guard: URL import (launch, paste, discovered configs) maps a single host plus `replicaSet` onto a one-element `Seeds` address, so the URI-spec meaning — discover from this seed — and `mongosh` parity are kept. A hand-written profile with `host` plus `replica_set` loads, but shows a notice that it connects directly to that one member with no failover and offers to convert it to `hosts = [..]`. Unit tests cover both mappings. Mitigating tasks: T-104.
- **Related decisions**: D-040, D-036
