## R-017: Credentials entering from the environment bypass the Secret wrapper

- **Severity**: medium
- **Likelihood**: medium
- **Disposition**: mitigate
- **Date**: 2026-07-31
- **Description**: Type-level redaction only protects values that are inside `Secret<String>`. Credentials that arrive by discovery — `DATABASE_URL`, a parsed `.env`, the stdout of the config-evaluating subprocess — arrive as ordinary `String` and stay unprotected across parsing, validation, and error construction. The window between "secret enters the process" and "secret gets wrapped" is exactly where connection-failure errors and debug logging happen, so the guarantee is weakest at the point the value is most likely to be printed.
- **Disposition rationale**: Medium severity at medium likelihood, but the unprotected window is exactly where connection-failure errors and debug logging happen. Closing it means moving the wrapper to the parse boundary, which changes no decision.
- **Action**: Guard: every credential-bearing parser — connection URL, `.env`, environment variable, `.pgpass`, `~/.pg_service.conf`, and the config subprocess's stdout — returns a struct whose password field is `Secret<String>` by construction, so no plain `String` credential exists at any point after the raw input bytes. The raw input is consumed and dropped inside the parser, never retained in an error or log line. Back it with a test or CI lint asserting that no struct on the connection path carries a plain-`String` password field. Mitigating tasks: T-022.
- **Related decisions**: D-020, D-012, D-013
