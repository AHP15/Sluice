## R-033: The no-keychain-access claim for the config subprocess does not hold on Linux

- **Severity**: high
- **Likelihood**: medium
- **Disposition**: mitigate
- **Date**: 2026-07-31
- **Description**: Denying the config subprocess keychain access is enforced by the platform's own scoping, and the platforms disagree. macOS scopes keychain items by application identity and Windows Credential Manager by user plus application, so a spawned `node` cannot silently read the app's items on either. libsecret has no such per-application boundary -- any process running as the user can read the session's secret service -- so on Linux, which D-019 ships as a first-class target, a consented config gets exactly the credential access the decision states it does not have. The mitigation's strength varies by platform while its wording does not.
- **Disposition rationale**: High severity at medium likelihood. The platform asymmetry is real and cannot be engineered away from inside the app on every distro, but the failure that matters is the *claim* — the decision promises an isolation property it does not uniformly have, and both the promise and the actual isolation can be improved.
- **Action**: Guard, three parts. (1) Consent text is platform-accurate: on Linux it states that the config runs with the user's full privileges including access to the login keyring, rather than repeating a macOS/Windows isolation claim. (2) Where a sandbox mechanism is available, use it — `bubblewrap` on Linux with the D-Bus session withheld, and note that Flatpak/Snap packaging supplies this for free; degrade to the accurate warning where it is absent. (3) Where D-007's encrypted-file fallback is in use rather than a secret service, the derived key and any unlocked material are held only in the app process and never reachable from a child. Residual, accepted knowingly: on a plain libsecret desktop with no sandbox available, a consented config can read the session's secrets, and the honest response is to say so at the consent prompt rather than to imply otherwise. Mitigating tasks: T-032.
- **Related decisions**: D-026, D-007, D-019
