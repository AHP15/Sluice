## R-002: Auto-discovered connections bypass every production guardrail

- **Severity**: high
- **Likelihood**: high
- **Disposition**: mitigate
- **Date**: 2026-07-31
- **Description**: The production flag, the DB-enforced read-only mode, and the history-off default are all properties of a saved *profile*. A connection discovered from the working directory has no profile, so none of them apply. A `.env` in a deploy or ops repository pointing at production means `dbc` silently opens a live read-write production session with query history recording, which is precisely the scenario the guardrails were written for.
- **Disposition rationale**: High severity and high likelihood — a `.env` in an ops or deploy repository is the common case, not the edge — but D-012's discover-and-connect behaviour is the best part of the product and worth keeping. The gap is that a discovered connection is not a profile, which is fillable without changing the decision.
- **Action**: Guard: discovery synthesizes an ephemeral in-memory profile carrying the full guardrail field set rather than a bare URL, defaulted conservatively — query history off, safety mode reported as `unknown` rather than assumed permissive, and the production-confirmation path armed by a host heuristic (any non-loopback, non-private-range host, or a database name matching production patterns). The UI shows the session as discovered-and-unsaved alongside its resolved host, and offers `save as profile` to opt into normal handling. Mitigating tasks: T-027.
- **Related decisions**: D-012, D-009, D-014
