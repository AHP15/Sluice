## R-011: The mongodb crate owns its own pool, so the pooling and session model does not map to it

- **Severity**: high
- **Likelihood**: high
- **Disposition**: fix
- **Date**: 2026-07-31
- **Description**: The connection model specifies a pool per profile with a reset on release plus a pinned dedicated connection per editor tab. The official `mongodb` crate exposes a `Client` that manages its own internal pool and does not hand out or take back individual connections, so there is no release hook to reset and no way to pin one. Neither half of the decision is implementable for Mongo, and because Mongo is the third engine, this is discovered after two engines have built on the model.
- **Disposition rationale**: High severity and high likelihood: neither half of the connection model is implementable on the third launch engine, and under D-022's ordering the discovery lands after two relational engines have calcified around it. The constraint is in the crate, so only changing the decision resolves it.
- **Action**: Superseded by D-028 — connection affinity and connection reset are now declared driver capabilities with defined absent-behaviour. Mongo declares `affinity: none`; its editor tabs run over the shared client with session-scoped state and interactive transactions stated as unavailable, rather than the model silently failing to apply. D-015 -> superseded.
- **Related decisions**: D-015, D-002, D-022
