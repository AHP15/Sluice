## R-047: SRV and TXT handling exist only behind the crate's connection-string parser, so typed options must be re-serialised into a URI

- **Severity**: medium
- **Likelihood**: medium
- **Disposition**: mitigate
- **Date**: 2026-11-07
- **Date resolved**:
- **Description**: In `mongodb` 3.9.1, SRV lookup and TXT option merging happen only when `ClientOptions` is parsed from a `mongodb+srv://` string (`HostInfo::DnsRecord` in `client/options.rs`); building `ClientOptions` field-by-field, as the T-087 driver does, has no SRV path. Honouring D-034's `Srv` and D-039 therefore means synthesising a URI from typed profile values, and any value not strictly validated and percent-encoded (an `auth_source` of `admin&tlsInsecure=true`, a crafted SRV name) re-opens the option-injection channel D-033 closed — including the TLS weakening it forbids.
- **Disposition rationale**: Medium severity at medium likelihood; synthesising a URI is unavoidable with this crate, so the guard is to make that one path impossible to inject through.
- **Action**: Guard: a single function builds the `mongodb`/`mongodb+srv` URI from typed D-042/D-040 values; every value is validated against a strict character set (hostnames, replica-set and database names) and percent-encoded, and a round-trip test parses the result and asserts the `ClientOptions` carry exactly the typed intent and nothing else — including adversarial inputs such as `admin&tlsInsecure=true`. Mitigating tasks: T-106.
- **Related decisions**: D-033, D-034, D-039
