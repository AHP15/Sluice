## R-018: The env-var-gated type-fidelity corpus sits outside CI and will rot unnoticed

- **Severity**: high
- **Likelihood**: high
- **Disposition**: mitigate
- **Date**: 2026-07-31
- **Description**: The corpus is the sole guard on the one decision identified as failing silently, and it is skipped unless a developer sets `TEST_PG_URL` by hand. An opt-in test that nothing runs is indistinguishable from an absent test after a few months: it passes at commit 100, is broken by a refactor at commit 400, and reports nothing. The failure is self-concealing, because the reason the test exists is that its subject produces plausible-looking wrong values.
- **Disposition rationale**: High severity and high likelihood, and the failure is self-concealing — an opt-in test nothing runs is indistinguishable from an absent one, while guarding the single decision identified as failing silently. D-021's local skip-by-default is worth keeping; what is missing is one place where the test actually runs.
- **Action**: Guard: extend D-019's existing CI matrix with one job that starts a Postgres service container, sets `TEST_PG_URL`, and runs the corpus — the test itself is unchanged and still skips locally by default, so D-021's no-ceremony property holds for developers. Make the skip loud in that job: CI fails if the corpus reports skipped or zero assertions, so a broken env var cannot present as a pass. Add the SQL Server and Mongo corpora to the same job as those engines land. Mitigating tasks: T-069.
- **Related decisions**: D-021, D-006
