## R-059: Adding the CA to the system roots weakens what `sslrootcert` and `tlsCAFile` users asked for

- **Severity**: medium
- **Likelihood**: low
- **Disposition**: fix
- **Date**: 2026-11-07
- **Date resolved**:
- **Description**: D-042 defines `tls_ca_file` as an extra trust anchor added to verification, never replacing it. In libpq `sslrootcert` and in Mongo `tlsCAFile`, the file *replaces* the trust store: only that CA is trusted, which users rely on to pin an internal CA. Mapping those parameters onto an additive anchor means any publicly trusted CA can also vouch for the hostname, so someone able to obtain a public certificate for that name (a DNS takeover, a mis-issued certificate) passes verification that the user's own configuration would have rejected.
- **Disposition rationale**: Medium severity at low likelihood, but no guard can repair it: D-042's text defined the anchor as additive, so honouring the engines' exclusive semantics required changing the decision.
- **Action**: Superseded by D-043
- **Related decisions**: D-042, D-007
