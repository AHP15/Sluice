## R-001: Running the CLI in any directory executes that directory's config as code

- **Severity**: critical
- **Likelihood**: medium
- **Disposition**: fix
- **Date**: 2026-07-31
- **Description**: Evaluating `drizzle.config.ts` by shelling out to `node` or `bun` runs whatever that file imports or computes. So `cd ~/Downloads/cloned-repo && dbc` executes arbitrary code from an untrusted repository, in a process that holds keychain access to every database the user has ever configured. The same exposure applies to PATH resolution: a project-local `node_modules/.bin` or a planted `bun` earlier on PATH is executed in preference to the system one.
- **Disposition rationale**: Critical severity with an entirely ordinary trigger — opening a cloned repository — and a blast radius of every credential the keychain holds. The exposure is written into the decision's own mechanism, so no guard layered on top of automatic execution would close it.
- **Action**: Superseded by D-026 — TS/JS config evaluation now requires explicit per-directory consent naming the config file's and interpreter's absolute paths, invalidated on content-hash change; the interpreter is resolved only from absolute system locations (never `node_modules/.bin` or a relative PATH entry), and the subprocess runs with a scrubbed environment, a timeout, and no keychain access. D-013 -> superseded.
- **Related decisions**: D-013, D-012, D-007
