## R-045: Production guardrails evaluate one configured host string, not the servers actually connected

- **Severity**: high
- **Likelihood**: medium
- **Disposition**: fix
- **Date**: 2026-11-07
- **Date resolved**:
- **Description**: `Guardrails::manual` / `ephemeral` call `production_reasons(host, database)` on a single host string (`src-tauri/src/guardrails.rs:139`), arming on any non-loopback host or production-looking name. Under D-034 a profile's address may be a seed list or an SRV name, and with discovery the connected members are whatever the replica-set config or DNS returns — so the guard is evaluated against a rendered label or the first seed (a loopback seed disarms it) while writes go to non-loopback, possibly production, members. D-027's production confirmation is only as good as the host it is shown.
- **Disposition rationale**: High severity at medium likelihood: a production confirmation evaluated against a label rather than the servers receiving writes defeats D-027, and the evaluation rule belongs in the address decision.
- **Action**: Superseded by D-040
- **Related decisions**: D-034, D-039, D-027
