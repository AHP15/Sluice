## R-003: The staged-edit preview can show a statement different from the one executed

- **Severity**: high
- **Likelihood**: medium
- **Disposition**: mitigate
- **Date**: 2026-07-31
- **Description**: The preview must render a human-readable statement with values inline, while execution must bind values as parameters. That means two code paths producing two artifacts from the same edit set, and nothing forces them to agree. Any divergence — quoting, type coercion, ordering, NULL handling — means the flagship safety feature displays a statement the database never runs, which is worse than showing nothing because the user has been told to trust it.
- **Disposition rationale**: High severity — the preview is the flagship safety feature and a divergence is worse than showing nothing, because the user has been told to trust it — but medium likelihood and the remedy is structural rather than a change of intent.
- **Action**: Guard: one statement builder produces the (statement, bound parameters) pair as a single artifact; the preview is a pure rendering *of that pair*, never a second build from the edit set, using a display-only quoting function. Property tests over generated edit sets assert that preview and execution derive from the same artifact across NULL, quoting, type coercion, and column ordering. Where a value cannot be faithfully rendered inline, the preview shows the parameterized statement plus a bound-value table rather than fabricating an inline literal. Mitigating tasks: T-057.
- **Related decisions**: D-009, D-005
