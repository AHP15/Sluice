## R-060: Certificate and key paths in a synced profile file break on every other machine

- **Severity**: low
- **Likelihood**: high
- **Disposition**: mitigate
- **Date**: 2026-11-07
- **Date resolved**:
- **Description**: D-042 stores `tls_ca_file` and client certificate/key as file paths in the profile file, which D-011 promises is portable and safe to commit or sync. Absolute paths are machine- and OS-specific (`/Users/alice/certs/rds.pem` against `C:\\Users\\...`), so a synced profile fails TLS on a teammate's or second machine with a missing-file error. The paths also embed local usernames and directory layout into a file meant to be shared (adjacent to R-019).
- **Disposition rationale**: Low severity at high likelihood; paths are the right representation, and portability is recoverable by how they are written and resolved.
- **Action**: Guard: certificate and key paths may be written relative to the profile file's directory or with a leading `~`, and the app writes them in that portable form where it can; a missing file fails with an error naming the profile, the key and the resolved path. PROFILE-FILE.md recommends keeping certificates beside the profile file (or under `~`) and warns that absolute paths embed local usernames. Mitigating tasks: T-100.
- **Related decisions**: D-042, D-011
