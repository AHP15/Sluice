## R-015: Sampling documents in natural order surfaces the collection's oldest schema

- **Severity**: medium
- **Likelihood**: high
- **Disposition**: mitigate
- **Date**: 2026-07-31
- **Description**: Column inference defaults to a cheap `find().limit(N)` in natural order, which for most collections returns the earliest-inserted documents. In any collection whose shape evolved — fields added, renamed, or migrated — the inferred columns are the legacy schema and current fields are simply absent from the grid. The user sees a confident, complete-looking table that omits the data they came for, and nothing signals the omission.
- **Disposition rationale**: Medium severity at high likelihood: any collection whose shape evolved renders the legacy schema confidently and with no signal, and the cheap default is precisely what causes it.
- **Action**: Guard: sample from both ends by default — a natural-order head plus an `_id`-descending tail — so recently written shapes are represented, and use `$sample` automatically below a document-count threshold where it is cheap. Show a persistent `columns inferred from N of M documents` indicator with a one-click deeper sample, and mark paths observed in only one of the two samples so schema drift is visible rather than silently resolved to the older shape. Mitigating tasks: T-064.
- **Related decisions**: D-018
