## R-027: Lazy introspection cannot supply the foreign-key graph relation navigation needs

- **Severity**: medium
- **Likelihood**: medium
- **Disposition**: defer
- **Date**: 2026-07-31
- **Description**: Loading columns and indexes only when a table is selected means the app never holds a global picture of foreign keys. Navigating from a row to its related rows — one of the features that makes Drizzle Studio worth copying — requires knowing inbound references from tables the user has not visited, which lazy per-table introspection has not read. The same gap blocks ERD rendering and any join suggestion, so a whole feature family is foreclosed by a decision made for connect latency.
- **Disposition rationale**: Medium severity at medium likelihood, and the blocked features — relation navigation, ERD, join suggestion — are all explicitly outside v1 per D-022, so nothing is broken today. Lazy loading is what keeps a 10k-table database usable and it does not preclude a whole-schema foreign-key load later; it simply does not supply one.
- **Action**: Defer with trigger: revisit at the first post-v1 scope definition that admits relation navigation, ERD, or join suggestion — or earlier if a user reaches for `follow this foreign key` and finds it absent. The resolution to evaluate then is an explicit, user-triggered whole-schema foreign-key load cached per connection (constraint catalogs only, not full column metadata), which is a bounded addition to D-016 rather than a reversal of lazy loading. Do not build it before that trigger.
- **Related decisions**: D-016, D-004
