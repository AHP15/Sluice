## R-049: Refusing unrecognised URL parameters breaks launches from ORM-style URLs that work today

- **Severity**: medium
- **Likelihood**: high
- **Disposition**: fix
- **Date**: 2026-11-07
- **Date resolved**:
- **Description**: D-037 refuses every parameter that is neither mapped nor ignore-listed, and applies it to CLI launches and config-discovered URLs alike. The most common Postgres URLs in project `.env` files are Prisma's, which carry non-libpq parameters such as `?schema=public`, `connection_limit=5`, `pgbouncer=true` and `sslaccept=strict`; today the launcher silently drops them and connects, after D-037 the same `sluice $DATABASE_URL` or discovered config is refused. Without those parameters on an ignore-list, the decision turns a working path into a regression for the most common source of URLs.
- **Disposition rationale**: Medium severity at high likelihood — the most common URL source would regress — and the remedy (honouring `pgbouncer=true`, admitting Prisma's parameters) needed D-037's classes and criterion to change.
- **Action**: Superseded by D-041
- **Related decisions**: D-037, D-012, D-026
