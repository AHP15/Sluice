## R-039: Declaring Mongo affinity: none forecloses ClientSession, which the crate does expose

- **Severity**: medium
- **Likelihood**: medium
- **Disposition**: mitigate
- **Date**: 2026-07-31
- **Description**: The premise carried from R-011 is that the `mongodb` crate hands out no pinnable handle, which is true of connections and false of sessions: `Client::start_session()` returns a `ClientSession` that carries causal consistency and is what multi-document transactions are started on, with the driver pinning the underlying connection for a transaction's duration. Declaring `affinity: none` therefore states in the contract and in the UI that interactive transactions are unavailable on Mongo when the driver supports them, so the capability model encodes a limitation of the first reading rather than a limitation of the engine -- and reversing it later means changing a declared capability two engines have already branched on.
- **Disposition rationale**: Medium severity at medium likelihood, and the decision's *structure* — affinity as a declared capability — is right; only one declared value rests on an unverified reading of the crate. Mongo is engine three and post-v1 per D-022, so nothing is built on `affinity: none` yet and the cheap guard is to not lock it in before checking.
- **Action**: Guard: define affinity as a three-valued capability from the start — `connection` (a socket can be pinned: Postgres, SQL Server), `session` (no socket pin, but a logical session carrying causal consistency and multi-document transactions can be pinned), `none` — and leave Mongo's declared value unset until a short spike confirms what `mongodb::Client::start_session()` and the `..._with_session` operation variants actually deliver for an editor tab. Run that spike alongside R-029's real-mongod contract check, since both need the same instance. If it confirms `session`, Mongo editor tabs get interactive transactions and the UI stops asserting they are unavailable; if it confirms `none`, the value is then declared on evidence. Flagged honestly: if the spike lands after D-028 has shipped and two engines have branched on the two-valued form, correcting it becomes a supersession rather than a guard — which is the reason to run it early. Mitigating tasks: T-045, T-046.
- **Related decisions**: D-028, D-002
