## R-040: Attaching a text span to each outcome forces the in-app SQL parsing the design rejected

- **Severity**: high
- **Likelihood**: high
- **Disposition**: mitigate
- **Date**: 2026-07-31
- **Description**: Mapping each statement outcome back to its source span requires splitting the script client-side, which means lexing the dialect: Postgres dollar-quoted function bodies (`$$ ... $$`, `$tag$ ... $tag$`) containing semicolons, T-SQL `GO` batch separators that are a client directive rather than a statement terminator, semicolons inside string literals, quoted identifiers, and comments. A naive split sends a truncated function body to the server as a syntax error on a script that runs fine in `psql`, and a subtly wrong split attributes an error to the wrong statement -- highlighting innocent text. D-009's rationale explicitly rejected in-app SQL parsing as a control, and the result shape now depends on it for correctness.
- **Disposition rationale**: High severity and high likelihood, but the danger is not that the app parses SQL — it is that *correctness depends* on parsing it right. Decoupling execution from attribution keeps D-029's sequence intact while making a mis-split cosmetic instead of destructive.
- **Action**: Guard: never rewrite or re-emit the user's text. The script is sent verbatim to the engine as a single batch (Postgres simple query, `tiberius` batch), so a splitter error can never manufacture a syntax error the user did not write. Splitting exists only to attribute outcomes for display, uses a real dialect-aware lexer (`sqlparser-rs` or equivalent) rather than a semicolon scan, and covers dollar-quoted bodies (`$$`, `$tag$`), `GO` batch separators, semicolons inside string literals and quoted identifiers, and comments in a test corpus. Make the text span optional on the outcome: when the splitter's statement count disagrees with the engine's result count, or the lexer reports low confidence, fall back to ordinal-only attribution with no highlighting rather than pointing at text that may be the wrong statement. Mitigating tasks: T-011.
- **Related decisions**: D-029, D-027
