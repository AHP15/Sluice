## R-058: Honouring `pgbouncer=true` as unnamed statements misses what transaction pooling also breaks

- **Severity**: medium
- **Likelihood**: medium
- **Disposition**: mitigate
- **Date**: 2026-11-07
- **Date resolved**:
- **Description**: D-041 maps `pgbouncer=true` to "unnamed statements only". Behind PgBouncer in transaction mode the Postgres driver's other session assumptions also fail: the statement timeout is sent as a startup `options` parameter (`crates/sluice-postgres/src/lib.rs:172`), which PgBouncer rejects at connect unless `ignore_startup_parameters` allows it; `DISCARD ALL` reset (`lease.rs`) and D-028's pinned editor sessions assume one server connection per client session, which transaction pooling does not provide, so `SET`s and `BEGIN`s in an editor tab can land on different server connections. The flag is honoured, but the profile still connects badly or not at all.
- **Disposition rationale**: Medium severity at medium likelihood; D-041 already says the flag is honoured as a declared driver behaviour, so the guard is to make that behaviour cover all of transaction pooling, not just statements.
- **Action**: Guard: under `pgbouncer=true` the Postgres driver uses unnamed statements (`query_typed`), sends no startup `options` and applies the statement timeout with `SET LOCAL` inside each transaction plus the D-010 client watchdog, declares `affinity: none` so D-028's absent-affinity behaviour applies (no pinned editor sessions), and declares `reset: not_applicable` since server connections are not the client's. A live test against PgBouncer in transaction mode covers connect, browse, a staged edit and the timeout. Mitigating tasks: T-105.
- **Related decisions**: D-041, D-028, D-010
