## R-048: The default auth source fails the most common local Mongo setup once a database is chosen

- **Severity**: medium
- **Likelihood**: high
- **Disposition**: mitigate
- **Date**: 2026-11-07
- **Date resolved**:
- **Description**: D-036 defaults `auth_source` to the profile's named database, else `admin`. The official `mongo` Docker image's `MONGO_INITDB_ROOT_USERNAME` user, and most hand-provisioned admin users, live in `admin`; a user who fills the connection dialog with that user and picks their app database to browse authenticates against the app database and gets a bare authentication failure. Matching `mongosh`'s rule is accurate, but `mongosh` users learn `?authSource=admin`; a GUI dialog that never shows auth source gives no clue why the right password is rejected.
- **Disposition rationale**: Medium severity at high likelihood; D-036's rule is the correct, mongosh-compatible default, so the fix is making the default visible and the failure explanatory.
- **Action**: Guard: the Mongo connection dialog shows the auth-source field with its effective default ("admin" or the chosen database) rather than hiding it, and an authentication failure whose effective auth source is not `admin` carries a D-017 hint: the user may be defined in `admin`; set auth source. A unit test covers the hint. Mitigating tasks: T-110.
- **Related decisions**: D-036
