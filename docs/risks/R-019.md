## R-019: Committed profile files leak production infrastructure topology

- **Severity**: medium
- **Likelihood**: medium
- **Disposition**: mitigate
- **Date**: 2026-07-31
- **Description**: Keeping secrets in the keychain makes the profile file "safe to commit", but the file still contains hostnames, ports, usernames, database names, and which environments exist. Committed to a public or widely-shared repository that is reconnaissance data: an inventory of production endpoints and valid usernames, which is most of what an attacker needs before credential stuffing. The safety property was established for credentials and then applied to the whole file.
- **Disposition rationale**: Medium severity at medium likelihood, and the exposure is bounded — the user chooses what to commit and the tool is local-only single-user. What is not acceptable is the unqualified `safe to commit` claim, which invites that choice without stating what the file still reveals.
- **Action**: Guard, documentation-weight and no format change: correct the `safe to commit` claim wherever it appears to state precisely what the file does and does not contain — no credentials, but hostnames, ports, usernames, database names, and the inventory of which environments exist. Ship the profile file with a header comment saying the same, and warn once on first save of a profile targeting a non-loopback host. Mitigating tasks: T-037.
- **Related decisions**: D-011, D-007
