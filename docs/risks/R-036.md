## R-036: Reopening the connection on release turns the SQL Server pool into connect-per-query

- **Severity**: high
- **Likelihood**: high
- **Disposition**: mitigate
- **Date**: 2026-07-31
- **Description**: `reopen` is declared per driver, and `tiberius` has no reachable reset -- so SQL Server takes the reopen path on every browse connection release. Each grid page, navigator expand, and filter change then pays a full TCP handshake, TLS negotiation, and login round trip, which against an encrypted or remote instance is typically 50-200ms of pure latency added to operations the pool existed to make cheap. The engine chosen as second precisely because it is needed day to day is the one where pooling stops functioning, and the cost is invisible in the design because it is spent per release rather than per query.
- **Disposition rationale**: High severity and high likelihood, and it is a self-inflicted regression — but the correctness property D-028 bought (never hand out a connection carrying another context's session state) does not actually require reopening on *every* release. It requires reopening on every release of a connection that was dirtied, and the pooled browse path structurally cannot dirty one.
- **Action**: Guard: reset-on-release becomes reset-if-dirty. A connection is marked dirty only when something session-mutating crosses it — raw passthrough SQL, an explicit `SET`/`USE`, temp table DDL, a prepared statement — and the structured browse compiler emits only parameterized SELECTs, which cannot mutate session state, so browse traffic never dirties a connection and never triggers a reopen. A dirty connection is reopened on release exactly as D-028 specifies. Keep one warm spare per profile so a genuine reopen is off the critical path, and instrument reopen rate so the cliff is measurable rather than assumed absent. Separately, spend part of the R-024 `tiberius` spike confirming whether a best-effort T-SQL reset script (session `SET` defaults, temp table cleanup) is sufficient to mark a connection clean without a reconnect. Mitigating tasks: T-040.
- **Related decisions**: D-028, D-022
