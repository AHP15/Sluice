## T-042: Single per-profile connection budget covering pooled and pinned

- **Status**: done
- **Size**: M

- **Acceptance**: One configurable ceiling governs pooled and pinned connections together, an idle pinned session is released LRU when a new tab would exceed it, and a tab holding an open transaction is never evicted — the new tab is refused with an explanation instead.

- **Notes**: The budget is the driver's pool ceiling. A pinned editor session
  is a lease from that same pool (T-041), so pooled and pinned connections are
  governed by one number. Tabs that connect to the same profile (keyed by id
  plus its full settings, so an edited profile doesn't reuse an old pool) now
  share one driver, held weakly so it closes with its last session. A launch
  is its own ephemeral profile (R-002), so its own budget. `connection_budget`
  on the profile is configurable (connect form field), default
  `DEFAULT_CONNECTION_BUDGET` = 5 per D-028's "~5". `open_editor` calls
  `Editors::make_room`: under budget, nothing happens. At budget, it releases
  the LRU pinned session that is idle, has no transaction and isn't running
  (rolled back and returned to the pool). That tab is told by the
  `editor-session` "released" event, and later runs are refused (tombstone)
  until it reconnects explicitly. If every session holds an open or failed
  transaction or is mid-run, the new tab is refused with an explanation. The
  pool now waits at most `BUDGET_WAIT` (30s) and then fails with a "budget in
  use" message instead of hanging. A browse floor inside the budget is T-044.
  Restricting release to provably stateless tabs, and the banner naming what
  was lost, is T-043.
