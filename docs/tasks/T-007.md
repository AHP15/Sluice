- **Notes**: `PgDriver` implements the full `Driver` trait over `tokio-postgres` with
  `deadpool-postgres` pooling, covering the four things the acceptance
  enumerates: connect (credentials proven at connect time, version banner
  captured), navigator tree, structured browse compilation, and raw passthrough.
  D-002 verified mechanically: `cargo tree --workspace` contains zero `sqlx`
  occurrences. 12 live integration tests pass against PostgreSQL 17. Pool is
  capped at 4 connections as a placeholder — T-042 owns the real per-profile
  budget. Capabilities are declared from measured behaviour, and the contrast
  with T-072's SQL Server findings is deliberate: Postgres declares
  `ResetSupport::Native` (`DISCARD ALL` exists), `CancelSupport::Native` (a
  protocol cancel request exists), and `max_idle_seconds: None` (unlike Mongo's
  60s ceiling from T-046). SCOPE NOTE: `apply_edits` is implemented as an
  explicit refusal pointing at T-056. That is deliberate — D-027 requires a
  unique-key gate and single-transaction application, and a half-implementation
  that writes without them would be worse than none. Editing is not among the
  four capabilities this acceptance enumerates and belongs to Phase 6.
