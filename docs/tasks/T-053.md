## T-053: Native catalog introspection loaded lazily with explicit refresh

- **Status**: done
- **Size**: L

- **Notes**: Already native-catalog (T-008: `pg_namespace`/`pg_class`) with
  schemas up front and relations on expand. Added the third level: relation
  kinds are now expandable to columns (`pg_attribute`, `format_type`, not
  null, ordinal order) and indexes (`pg_index` + `pg_am`: method, unique,
  primary key), resolved by bound (schema, name) — so clicking a table both
  browses it and lists its structure. The T-008 invariant "a kind is exactly
  one of container / relation" was replaced: relations are both, and the new
  leaf kinds (`column`, `index`, `notice`) are neither. Per-connection cache
  in `PgDriver` keyed by parent `NodeId`, shared across `with_*` copies.
  Invalidation after the app's own DDL is conservative:
  `script_may_change_catalog` keeps the cache only when every statement
  starts with a known non-catalog keyword; `DO`, `CALL`, `GRANT`,
  unrecognised statements, or an unconfident split invalidate. Explicit
  refresh: `refresh_navigator` command + a Refresh button that drops the
  cache and remounts the tree. Rendering around failures: permission-denied
  on a catalog read becomes a `notice` node (not cached, so the next expand
  retries), and a relation dropped since load yields a "no longer exists —
  refresh" notice instead of an error. Verified live with a second connection
  as "someone else": external DDL stays invisible until refresh, the app's own
  DDL invalidates on its own, DML does not, and a vanished relation is a
  notice. Permission-denied is unit-tested only — producing it live needs
  revoking catalog privileges from PUBLIC, which would break concurrent tests.
