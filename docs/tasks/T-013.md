- **Date dropped**:
- **Notes**: Much was already in place from T-009 — the wire `FilterTree`
  (And/Or/Pred) and most comparison operators with parameter binding. Added:
  D-005's universal core as a contract constant (`CORE_FILTER_OPS`) with a
  conformance check (`missing_core_ops`) every driver's tests run; Postgres now
  compiles and declares the missing `in` (array value, each element bound with
  the column cast; an empty list compiles to `FALSE`), `between` (exactly two
  values, inclusive) and declares `ends_with`. Comparing with NULL via
  `eq`/`ne`/`in`/`between` is refused with a pointer to `is_null` — `col =
  NULL` is a silently empty result, the "valid but semantically wrong query"
  D-005's rationale warns about. Type classes: the existing `TypeClass` is a
  refinement of D-005's list (number → Integer/Float/ExactNumeric, json and
  array → Structural, geo → Opaque), kept rather than coarsened. Unit tests:
  every core op compiles with a hostile value never reaching the SQL text, plus
  shape, NULL and grouping cases. Live test (`filters_live.rs`, in the CI
  Postgres gate): each core op against a real table, including a quote-bearing
  value, a literal `%`/`_` needle and NULL rows, and it fails if a core op
  lacks a case. The filter-bar UI is not in scope (T-014 renders operators).
