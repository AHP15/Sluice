## T-043: Restrict LRU eviction to provably stateless tabs and never reconnect silently

- **Status**: done

- **Notes**: "The app can show" is done by asking the server, not by scanning
  statements. A statement scan can't prove statelessness:
  `SELECT set_config(...)` and `SELECT pg_advisory_lock(...)` change session
  state with no `SET`. `PinnedSession::held()` runs one simple query for
  session-sourced settings (`pg_settings.source = 'session'`), temp tables in
  `pg_my_temp_schema()`, SQL-level prepared statements (`from_sql`), named
  cursors, this backend's advisory locks and `LISTEN` channels, plus the
  probed transaction. A failed block counts as holding a transaction. It is
  refreshed after every run and control, shown in `SessionStatus.holds`, and
  re-checked fresh inside `make_room`. Only a session reporting nothing is
  LRU-releasable; anything else, or a session whose state can't be checked,
  makes it ineligible, and the refusal names what is held. Postgres has no
  `USE`, so it isn't checked here; SQL Server's equivalent belongs with that
  driver. Banners name what was lost via `lost_message`: a release says it
  held no session state, and a connection loss lists the last-reported state
  plus "rolled back, never committed" when a transaction was open. Both are
  persistent, and every later run is refused until the explicit Reconnect
  (T-041/T-042). Live tests cover each of the seven kinds of state, including
  `set_config` with no `SET`; the release test confirms a stateful pair is
  refused while a stateless third is released.
