## T-041: Pinned editor sessions with opt-in explicit transactions

- **Status**: done
- **Size**: M
- **Implements**: D-028
- **Depends on**: T-039
- **Acceptance**: Each SQL editor tab on an affinity-capable engine pins a dedicated connection for its lifetime, transactions are opt-in with a persistent indicator, auto-rollback on idle timeout, rollback rather than commit on tab or window close, and connection loss is surfaced explicitly rather than silently reconnected.

- **Notes**: Each workspace tab already owns one driver and one editor, so the
  editor pins one pool `Lease` (marked dirty) for the tab's lifetime. On close
  it goes back through the declared reset, and T-042 owns sharing a budget
  across tabs. The webview opens it only when `editorSessionPolicy` says
  `pin: socket`, and the core re-checks the declared affinity. Transactions
  are opt-in (Begin control or a typed `BEGIN`). After every run the session
  probes the server with `statement_timestamp() <> transaction_timestamp()`
  over the simple protocol; the extended protocol read every idle session as
  open. 25P02 on the probe means `Failed`. `ExecutionResult.tx` is corrected to
  `ExplicitUser`/`Open`. When the script itself ends a transaction, the outcome
  comes from `txid_status` on the xid seen while open. New
  `TxDisposition::Unknown` is used where that can't be known (no xid yet),
  rather than guessing "committed". A core reaper (every 20s) rolls back open
  transactions idle past `IDLE_TRANSACTION_TIMEOUT` (15 min, a default chosen
  here; D-028 names no value) and emits `editor-session`. Tab close,
  disconnect and window `Destroyed` roll back and release; never commit. A
  dropped connection marks the session lost, every later run is refused with
  what was lost, and the UI requires Reconnect, which opens a new session.
  The persistent `EditorSessionBar` shows autocommit / open (with
  auto-rollback rules) / failed (rollback only) / lost. Run never falls back
  to a pooled connection when the editor is pinned. The raw-script body was
  extracted into `run_script`, shared by the pooled and pinned paths. Live
  tests cover session state persisting, opt-in commit/rollback,
  close-rolls-back, script-ended transactions, the failed block, and
  `pg_terminate_backend` loss. Reaper and close tests are in src-tauri.
  `close_editor` was initially unguarded; the T-006 boundary test caught it.
