- **Status**: done
- **Size**: M
- **Implements**: D-016
- **Depends on**: T-053
- **Acceptance**: Connect parses `version()` for both server version and flavour, records both in the connection's capability descriptor, and catalog queries and features gate on them.

- **Date dropped**:
- **Notes**: `version::parse` turns the `version()` banner into a flavour
  (Postgres, CockroachDB, Redshift, YugabyteDB, Greenplum, or `Unknown` with
  the banner's first line — never guessed vanilla), the product's own version
  and the PostgreSQL version whose catalogs it presents; unit-tested against
  seven real banner shapes. The descriptor now carries a clean
  `server_version` (e.g. `17.11`, not the banner) and `flavour`. Gates that
  actually change behaviour: the T-015 collation probe runs only where
  `pg_collation.collisdeterministic` exists (vanilla/Greenplum on PG 12+) —
  elsewhere it is skipped instead of failing connect; Redshift (no `DISCARD
  ALL`) declares `reset: reopen_only` per D-028; the navigator hides each
  flavour's internal schemas (`crdb_internal`, `gp_toolkit`, `pg_automv`) via
  a bound `<> ALL($1)`. The banner is now read first, in its own query, so
  nothing flavour-specific runs before the flavour is known. Verified live:
  postgres:17 → `postgres 17.11`, native reset, collation probed. Only vanilla
  Postgres was exercised live; the other flavours are banner-parsing and gate
  unit tests. Timescale and PgBouncer cannot be seen in `version()` — T-055's
  feature probes own those, and T-055 also owns displaying an unknown flavour
  as "vanilla, unverified".
