- **Notes**: There was no logging before this. `tracing` writes JSON lines to
  `<cache>/sluice/logs/sluice.log`, rotated **by size** (5 MB × 3 files; custom
  `SizeRotatingFile`, since `tracing-appender` only rotates by time). Shape-only
  is structural: `diagnostics::query_event` is the sole query-logging entry
  point and its parameters are shape-typed (static kind, row count,
  `ErrorKind`) — no argument can carry a parameter value, a row, or an error
  *message* (which can quote data, e.g. a duplicate key). A test forbids
  `tracing` macros in any other module of the crate (negative-controlled: a
  stray `tracing::info!` in another file fails it). Commands log via
  `logged(...)`: connect, navigator, browse, browse_stream, script,
  fetch_value; the profile id is the session id's prefix, never the token.
  Verbose diagnostics: a process-wide flag, off at every launch, toggled from
  the Diagnostics panel; only `run_script` passes its text, which is dropped
  unless verbose is on. Until T-025 lands, verbose can capture a `CREATE ROLE
  … PASSWORD` literal — the toggle says so. Panic hook writes
  `<cache>/sluice/crashes/crash-<ms>.txt` (version, platform, thread,
  location, message, forced backtrace), keeps the newest 5, logs only the code
  location, then chains to the previous hook so T-006 still converts driver
  panics. Copy diagnostics: the core builds the text (version, platform,
  verbose state, latest crash, last 200 log lines); the panel shows all of it
  and copies that same string. Verified in the built app: a URL launch wrote
  `connect` and `navigator` events with kind/profile/duration/rows and no URL
  or password. Also cleaned `target/`: the folder rename had left Tauri build
  outputs pointing at the old absolute path.
