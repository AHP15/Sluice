- **Notes**: Secrets go through the `keyring` crate (macOS Keychain / Windows Credential
  Manager / libsecret) with a ChaCha20-Poly1305 encrypted-file fallback for
  hosts with no secret service, and `Backend` reports which one answered so a
  silent downgrade is visible rather than assumed. The core resolves a profile
  id to a credential inside `connect`, at connect time, and the resolved
  password goes straight into the driver's `ConnectSpec` — whose `Debug` is
  hand-written to print `<redacted>`, tested, so a stray log line cannot leak
  it. "No IPC response carries a credential" is enforced structurally rather
  than by discipline: `ProfileMeta` is the only connection shape crossing IPC
  and has no secret field, asserted by serializing a fully-populated one and
  checking for password-shaped keys; `store_credential` is the single
  secret-accepting command and its success type carries only which backend was
  used. Fallback tests go past the happy path: the ciphertext is checked not to
  contain the plaintext, tampering is detected by the AEAD rather than returning
  garbage, files are 0600, and profile ids cannot traverse out of the credential
  directory. Honest about the fallback's limit, in a comment at the key
  derivation: with no secret service there is nowhere safe for a master key, so
  it sits beside the ciphertext with tight permissions — that defends against
  casual reads, stray backups and sync clients, not against a local attacker
  already running as this user. D-007 accepts that tradeoff explicitly.
