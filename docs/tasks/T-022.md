## T-022: Wrap credentials in Secret<String> at every parse boundary

- **Status**: done
- **Size**: M
- **Implements**: D-020
- **Mitigates**: R-017
- **Acceptance**: Every credential-bearing parser — connection URL, `.env`, environment variable, `.pgpass`, `~/.pg_service.conf`, and config subprocess stdout — returns a struct whose password field is `Secret<String>`, and a CI lint fails on any plain-`String` password field on the connection path.
- **Evidence**:
  - `symbol:crates/sluice-core/src/secret.rs:pub struct Secret<T>`
  - `symbol:crates/sluice-core/src/secret.rs:pub const REDACTED`
  - `grep:pub password: Option<Secret<String>> in crates/sluice-postgres/src/lib.rs`
  - `grep:secret: Secret<String> in src-tauri/src/commands.rs`
  - `grep:-> Result<Secret<String>, CredentialError> in src-tauri/src/credentials.rs`
  - `test:crates/sluice-core/tests/credential_lint.rs`
  - `grep:credential-lint in .github/workflows/build.yml`
- **Date done**: 2026-08-03
- **Date dropped**:
- **Notes**: `Secret<T>` implements `Deserialize` but deliberately **not**
  `Serialize`. The asymmetry is the mechanism: a parser can land a credential
  *already wrapped* (closing R-017's "window between secret enters and secret
  gets wrapped"), while putting one in an IPC response becomes a compile error
  rather than a review catch — which is D-007's boundary enforced by the type.
  `ConnectSpec`'s hand-written `Debug` was deleted in favour of a derived one;
  the old impl worked but was exactly the per-call-site remembering D-020
  rejects. Scope note for the acceptance's parser list: of the six named
  parsers, only the keychain/file credential store and the IPC boundary existed
  at this point — connection URL, `.env`, environment, `.pgpass`,
  `~/.pg_service.conf` and config-subprocess stdout are built by T-028/T-029.
  This task therefore ships the type plus the enforcement so those parsers are
  born compliant, and the lint is what fails their build if they are not; it was
  negative-controlled by injecting `legacy_token: String` into
  `crates/sluice-postgres/src/lib.rs` and confirming the lint failed, then
  reverting.
  Deliberately NOT in scope: zeroize-on-drop. R-017 is about credentials
  reaching logs and error strings, not memory scraping; adding it would be a
  different threat model and a new dependency.
