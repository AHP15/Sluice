- **Notes**: The gate is `EditGate` (editable by key, or read-only with a
  reason). Postgres derives it from the catalog: the primary key, else the
  narrowest unique index whose key columns are all NOT NULL (non-partial,
  non-expression, `INCLUDE` columns excluded). Views, matviews, keyless tables
  and NULL-admitting unique keys are read-only. A structured browse reports
  the gate (stream `columns` event and `ExecutionResult.edit`). `apply_edits`
  re-derives it from the catalog rather than trusting the webview. It compiles
  every edit before `BEGIN`, requires each `UPDATE` to hit exactly one row, and
  otherwise rolls back the whole batch, reporting a `Conflict` at that edit's
  ordinal (verified live, including a CHECK violation, with the connection
  reusable afterwards). Webview: `pendingEdits.ts` stages cells (editing back
  to the value as read un-stages), and the grid offers Apply / Discard /
  per-cell revert. There is no post-commit undo. Switching relation or running
  a query is refused while edits are pending, so they are never dropped
  silently. Integer and float input travels as the literal text typed and is
  cast by the database, so the edit path holds no JS number conversion at all.
  `pendingEdits.ts` and `CellEditor.tsx` were added to
  `check-exact-numeric.mjs`. Until T-058, every original is reported in
  `concurrency_omitted`, so no result claims a concurrency guarantee. No
  preview of the statement yet; that is T-057's.
