- **Notes**: mongodb 3.9.1, default features (rustls). No bb8/deadpool: the crate's own pool gets `max_pool_size` = budget (min 0, 5-min idle close), and polling monitoring keeps the extra monitor socket to one per server. The live test saturates a budget of 2 with 8 slow finds and sees exactly 2 busy sockets plus the monitor. Single host with `directConnection`, as mongosh does. Credentials authenticate against the profile's database, the way a URL path works. Capabilities: `affinity: session`, `reset: not_applicable`, `cancel: none`, `raw_payload: command_document`, `supports_script: false`, `fixed_schema: false`. Transactions are interactive with `max_idle_seconds` read live from `transactionLifetimeLimitSeconds` (60 if the login can't read it). They are declared absent on a standalone server, per T-046. Navigator: `database → collection | view` via `authorizedDatabases` / `authorizedCollections` and `listCollections nameOnly`. admin/config/local and `system.*` are hidden. Results are cached until refresh, notices are never cached, and permission errors show as notes (D-016). Browse, raw, edits, export and pinned sessions return "not available on MongoDB in this build" (T-088/T-089). The live test ran against mongo:8 rs0 (env `SLUICE_TEST_MONGO_PORT`) and re-ran T-046's interactive two-collection transaction through `.session(&mut s)`.
