- **Notes**: New sluice-core::redact_statement, the single filter both persistence paths call: targeted replacement of the literal after a password keyword (PASSWORD / ENCRYPTED PASSWORD / IDENTIFIED BY / pwd: / @rmtpassword = / PASSWORD(…)), then redact_shapes for conninfo and URL userinfo inside dblink/postgres_fdw literals, then a fallback that redacts every literal (and any keyword-bearing comment) when a keyword matched nothing, and whole-text replacement when a keyword-bearing statement cannot be tokenized. Tokenizer handles '' / E'' / $tag$ / SQL double-quoted identifiers, and Mongo-shell double, single and backtick strings. Applied in diagnostics::query_event before the formatter (so the copy-diagnostics preview, built from the log, is covered) and in record_history before the store sees the text. History entries flagged redacted are badged 'not replayable' and cannot be loaded back into the editor.
