- **Notes**: Inference is a pure, engine-neutral module in `sluice-core` (`schema_infer::infer_columns`). It takes an optional JSON-Schema validator (wrapped in `$jsonSchema` or bare) and a sample of the core's own `WireValue` documents, and returns ordered `InferredColumn`s with presence/null counts, observed and declared type tags, a `type_varies` marker and a source. Validator paths come first: `_id`, then `required` order, then the rest by name, because serde_json is built without `preserve_order` so property order cannot be relied on. Paths seen only in the sample follow, by descending frequency and stable on first-seen order, so a validator never hides a field a document actually carries. A declared-vs-observed type mismatch is marked, never rejected. `null` counts as presence, not as a type, and `Missing` counts as absent. Arrays are never descended. Nested documents stay one cell by default (`max_depth: 1`) so every column keeps its positional edit identity; deeper paths are available on request, and the sample is capped by `sample_limit`. The capability is `Capabilities::column_inference: ColumnDerivation` (`catalog` | `inferred { validator, sample_limit, deep_sample }`), `serde(default)` = catalog. Because `Capabilities` is built by struct literal, postgres and sqlserver each gained one `column_inference: ColumnDerivation::Catalog` line, and any new driver literal (the Mongo crate, T-087) must declare it too. A pure `infer_columns` Tauri command re-runs inference on a supplied sample. In the UI, `columnLayout.ts` holds pin/hide/reorder/manual-add as pure layout operations, a never-converting `pathValue` lookup, and an in-memory per-collection `layoutCache`. Page columns the inference does not name are still shown, and hidden columns are always offered back. `ResultGrid` takes an optional `layout` prop and shows header controls, a frequency label and a layout bar with an explicit "Refresh columns". The grid infers only when nothing is cached for the key or when the user refreshes. Nested or added paths render read-only (editability is T-062). `App` passes `layout` only when the session declares `inferred`, using the page in view as the sample until T-064 supplies a dedicated one. Not done here: the raw document view D-018 also mentions (not in this Acceptance), sampling both ends (T-064), and persisting layouts across restarts (the cache is per app session).
