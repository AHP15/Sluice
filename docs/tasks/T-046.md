## T-046: Spike: verify what mongodb ClientSession delivers for an editor tab

- **Status**: done
- **Size**: S
- **Mitigates**: R-039
- **Acceptance**: A written verdict states whether `Client::start_session()` and the `..._with_session` operation variants support causal consistency and interactive multi-document transactions well enough for an editor tab, concluding with the affinity value Mongo should declare.
- **Evidence**:

- **Date done**: 2026-08-02
- **Date dropped**:
- **Notes**: Verdict is `affinity: session`. R-039's premise confirmed on every
  point: an interactive multi-document transaction held open across two
  collections and an application-controlled await showed real snapshot
  isolation (outside=0, inside=1), commit and abort both behaved, and
  `causal_consistency(true)` tracked operationTime. Two corrections to R-039's
  text: the `..._with_session` variants it names are the mongodb 2.x API,
  replaced in 3.x by `.session(&mut s)` on the action builder, so T-045 must not
  be written from the risk text verbatim; and a replica set is mandatory, as a
  standalone mongod cannot transact at all. Caveat that does not change the
  verdict: `transactionLifetimeLimitSeconds` is 60s by default, so the server
  kills an idle editor-tab transaction where Postgres and SQL Server would hold
  it indefinitely — `affinity` declares that a session can be pinned but says
  nothing about how long the pin survives. That gap is a NEW RISK not in the
  recorded set; routed to triage-risks, not decided here.
