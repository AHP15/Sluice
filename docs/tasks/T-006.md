## T-006: Contain driver panics without leaving poisoned or leaked state

- **Status**: done
- **Size**: M
- **Implements**: D-003
- **Mitigates**: R-022
- **Depends on**: T-005
- **Acceptance**: Every IPC command boundary is wrapped in `catch_unwind`, locks are non-poisoning or explicitly re-initialized on poison, pooled connections return via RAII guards that run during unwind, and a caught panic tears down the affected connection and surfaces a `driver bug` error naming the session.

- **Notes**: All four clauses covered and tested (12 tests in sluice-core, 3 in
  the app). (1) `guard_driver_call` / `guard_driver_call_blocking` wrap driver
  calls, with the async form using `FutureExt::catch_unwind` because
  `std::panic::catch_unwind` cannot contain a panic across an await. Every IPC
  command routes through it, and that is ENFORCED rather than reviewed: a test
  reads `commands.rs`'s own source and fails any `#[tauri::command]` defined
  without the guard — plus a negative-control test proving the scan can fail.
  (2) `NonPoisonMutex` recovers explicitly via `into_inner()` on poison, tested
  by panicking while holding the lock and asserting the state is recovered
  rather than the app wedging; `was_poisoned()` is retained so T-023 can surface
  "state may be inconsistent". (3) `ConnectionLease` is an RAII guard whose
  `Drop` runs during unwinding. (4) The load-bearing line is
  `std::thread::panicking()` in that `Drop`: while unwinding the connection is
  `discard`ed with `DiscardReason::Panic` instead of released, because T-072
  measured a tiberius decode panic leaving the TDS stream mid-packet. Caught
  panics surface as `ErrorKind::DriverBug` naming the session, with the panic
  payload in `engine_detail`. `ConnectionHome` is a trait so this could be built
  and tested before T-039's pool exists; the pool implements it later. A debug-only
  `debug_panicking_driver_call` command exists to exercise the path end to end
  from the webview. Worth noting for R-022's eventual re-triage: T-072 measured
  the connection as still usable after a caught tiberius panic, which is better
  than the risk assumed — but that is an accident of where the `todo!()` sits,
  so the discard-on-panic policy does not rely on it.
