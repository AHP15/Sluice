- **Notes**: One structured request — relation, filter tree, sort list, page cursor —
  compiled by the driver into native SQL; the grid issues only that and never
  builds SQL. Parameters are always bound and are sent as text then cast
  (`($1)::text::numeric`), which keeps one code path per type AND keeps exact
  numerics off the f64 path on the write side, mirroring what D-006 prevents on
  the read side. Non-obvious bug found and fixed during live testing:
  `($1)::int4` makes PostgreSQL infer the *parameter* as int4, so sending text
  fails with "error serializing parameter 0" — routing through `::text::` first
  pins the parameter to text. Identifiers are quoted with doubled embedded
  quotes, tested against a relation name containing `"; drop table users; --`.
  `LIMIT` is clamped rather than trusted. R-009 is honoured concretely:
  `contains` compiles to `ILIKE` (case-INSENSITIVE) with LIKE metacharacters
  escaped, matching the behaviour the Mongo spike driver was made to adopt, and
  `FilterOpDecl.case_sensitive` declares it. Undeclared operators are refused
  rather than guessed. Keyset cursor compiles to a range predicate in sort
  direction; T-047/T-048 own the full multi-column form.
