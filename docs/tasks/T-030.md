## T-030: Broaden the consent fingerprint beyond the config file

- **Status**: done
- **Size**: M
- **Implements**: D-026
- **Mitigates**: R-031

- **Acceptance**: Consent is keyed to a fingerprint covering the config hash, every lockfile present, and the hashes of local files named by the config's relative import specifiers found by a non-executing scan, with a re-prompt on any change, on interpreter path change, and after a disuse TTL.

- **Notes**: Fingerprint v2 = config hash + interpreter path (unchanged) +
  `additional_hashes`: every lockfile (`package-lock.json`,
  `npm-shrinkwrap.json`, `pnpm-lock.yaml`, `yarn.lock`, `bun.lock`,
  `bun.lockb`) in the nearest directory that has one, walking up from the
  config but stopping at a `.git` root — monorepos keep the lockfile at the
  workspace root — plus each local file the config names by relative specifier
  (`import … from`, side-effect `import`, `export … from`, `import()`,
  `require()`), resolved by exact path, ESM `.js`→`.ts`, extension probing and
  `index.*`. An unresolvable import is hashed as `unresolved`, so the file
  appearing later re-prompts. The scan is lexical and inert (classified in the
  `no_subprocess` lint). **Shallow by design** — direct imports only: following
  them transitively reaches app code like `./src/db/schema`, and re-prompting on
  ordinary edits is consent fatigue; a test asserts unrelated edits do not
  re-prompt. R-031's residual (a deep edit changing no lockfile and no direct
  import) stays accepted. Bumping `FINGERPRINT_VERSION` to 2 makes every
  existing v1 grant re-prompt once. Disuse TTL: 90 days since `last_used_at`,
  which every evaluation refreshes, so a project in daily use never expires;
  a clock running backwards does not expire a grant.
