## T-017: Unknown type OID fallback so exotic types reach the UI as strings

- **Status**: done
- **Size**: M
- **Implements**: D-006
- **Mitigates**: R-014
- **Depends on**: T-016
- **Acceptance**: A Postgres column whose type OID has no known mapping is delivered as a tagged string via text-format request or raw-bytes passthrough with its type name resolved from `pg_type`, and a table containing PostGIS geometry, `tsvector`, a domain, and an extension enum browses without error.
- **Evidence**:
  - `grep:TextShape::Exotic in crates/sluice-postgres/src/encode.rs`
  - `grep:unknown_oids_fall_through_to_exotic_rather_than_failing in crates/sluice-postgres/src/encode.rs`
  - `grep:exotic_types_browse_without_error_and_arrive_as_tagged_strings in crates/sluice-postgres/tests/live.rs`
  - `grep:postgis_geometry_browses_when_the_extension_is_available in crates/sluice-postgres/tests/live.rs`
- **Date done**: 2026-08-03
- **Date dropped**:
- **Notes**: R-014 is retired, and by a route that removes the failure mode rather than
  handling it: because non-native columns are rendered server-side as text, a
  type with no Rust mapping needs no Rust mapping. The `_ =>` arm of
  `rendering_for` is the default path, not an error path — an unknown OID is
  ordinary. Verified live against real extension types, all browsing without
  error and arriving as `WireValue::Opaque` carrying the engine's own type name:
  `tsvector`, a user-defined enum, a domain over int, `int[]`, `int4range`,
  `inet`, `macaddr`, `bit(8)`, `interval`, and — on an `imresamu/postgis:17-3.5`
  container — **PostGIS `geometry(Point,4326)`**. Two honest notes on the
  acceptance's wording: the enum exercised is a user-defined `CREATE TYPE ...
  AS ENUM` rather than one shipped by an extension, which is the identical code
  path (unrecognised OID -> server-rendered text); and the type name is resolved
  from the prepared statement's type metadata, which tokio-postgres populates
  from `pg_type`, rather than by a hand-written `pg_type` query. Also worth
  recording for T-004: `postgis/postgis` publishes no arm64 image, so
  `imresamu/postgis` is the multi-arch alternative T-069 will need.
