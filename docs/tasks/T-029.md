- **Notes**: Structure: policy in `sluice-config` (fingerprint, interpreter
  validation, consent store, the gated evaluator), decision injected through a
  `ConsentPrompt` trait, native dialog in `src-tauri/src/consent_dialog.rs`.
  The dialog is native rather than a webview modal for two structural reasons —
  D-012's launcher must be able to ask *before* the webview exists (a webview
  modal forces "evaluate first, ask later", which is R-001 exactly), and the
  prompt asking "may this repository's code run" must not share a surface with
  content that repository could influence.
  `evaluate.rs` is the only module in the crate that may spawn, enforced by
  T-028's `no_subprocess` lint; `interpreter.rs` resolves paths without
  executing, so it stays on the inert side.
  **`PATH` is never consulted.** D-026 enumerates two sources (user-configured
  path, system install directory) and neither is `PATH`; filtering `PATH` to its
  absolute entries would still honour one an rc file or direnv had pointed into
  the project. Cost: `nvm` installs are not auto-detected and need an explicit
  configured path — the safe failure direction, since D-026's degradation is a
  working app.
  Interpreter validation rejects non-absolute paths, any `node_modules`
  component, anything under the scanned directory, and — after canonicalizing —
  symlinks that launder a project-local binary through a trusted-looking
  location. A rejected *configured* path surfaces the rejection rather than
  falling through to a system search.
  R-001 is tested end-to-end, not just at the gate:
  `declining_really_does_not_execute_the_config` writes a config whose side
  effect is an `EXECUTED` marker file and asserts it is absent after a decline,
  and `the_non_execution_test_has_a_working_control` runs the same config with
  consent and asserts the marker *does* appear — without the control the first
  test would pass even if evaluation were broken entirely. Both run in CI.
  Fingerprint carries `fingerprint_version` and an `additional_hashes` map so
  T-030's broadening invalidates existing grants instead of silently honouring
  ones computed under the narrower definition.
  Two things deliberately left to their own tasks: `EnvPolicy::Minimal`
  implements D-026's literal "minimal scrubbed environment", which R-032
  (high × high) says silently changes which database opens — **T-031 replaces
  it**; and the dialog's blast-radius text is a first platform-accurate cut that
  **T-032 (R-033) owns**. A test already asserts the Linux wording does not
  repeat the macOS/Windows keychain-isolation claim.
