- **Status**: done
- **Size**: M

- **Notes**: 68 Postgres cases, each checked three ways: read equals the
  expected `WireValue`, the JSON round trip is identity, and **write-back**
  (the read value bound as an `eq` parameter through the same text-and-cast
  path an edit uses must find the row — R-005's edit round-trip). Gated on
  `TEST_PG_URL`, skips by default, and prints `TYPE-CORPUS: SKIPPED` or
  `TYPE-CORPUS: N cases, M checks, K failure(s)` for T-069 to gate on. Run
  green against `postgres:17` (270 checks). The first run found **three real
  D-006 bugs**, all fixed here: (1) `NaN`/`±Infinity` floats serialized as JSON
  `null`, so the grid showed them as SQL NULL and Rust could not deserialize
  them — now tagged `Opaque` strings in Postgres' spelling (`float_to_wire`);
  (2) bytea parameters were bound as `($1)::text::bytea`, storing the base64
  *characters* as bytes — every bytea filter/cursor (and any future edit)
  was silently wrong; now `decode($1,'base64')` (`typed_param`); (3)
  `serde_json`'s default float parser is up to one ULP off, so floats returned
  from the webview drifted — enabled `float_roundtrip` workspace-wide. Engine
  facts recorded: Postgres `text` cannot hold U+0000 and `jsonb` rejects
  `\u0000`, so the NUL cases are `bytea` and verbatim `json` plus an assertion
  that a text NUL is rejected loudly. **Not covered: `Decimal128` at the engine
  level** — no Mongo driver exists (D-022 sequences it third); its extremes are
  asserted at the wire-contract level in `sluice-core`, and a Mongo corpus
  should sit beside this one when that engine lands (R-018's Action). PostGIS is
  not in the corpus: `postgis/postgis` has no arm64 image; the existing
  `postgis_geometry_browses_when_the_extension_is_available` covers it where
  available.
