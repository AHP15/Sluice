- **Notes**: Grammar is a pure, unit-tested module (`sluice-config::launch`,
  classified inert in the `no_subprocess` lint): no args → discover the cwd; a
  bare argument → URL if it parses, else a directory resolved against the
  *invoking* process's cwd; `--profile <name>` / `--profile=<name>`; reserved
  subcommand words refused with the escape spelled out (`sluice -- query`,
  `sluice ./query`); unknown flags and extra positionals are errors; macOS
  `-psn_*` ignored; error text never echoes a password. Discovery order: inert
  sources first (env, `.env`, JSON/TOML, no prompt), else the consent-gated
  TS/JS path (T-029/T-031) with the native consent dialog and then the
  target-confirmation dialog; a declined or interpreter-less config degrades to
  the connect form with its reason; a failing config is a visible error. D-007:
  a launched URL (and inline password) is parked core-side under an opaque
  `launch_id`; the webview gets only that id and a credential-free target, and
  `connect_launch` connects in the core. `sslmode` maps onto D-007's modes
  without weakening the default (`prefer`/absent → Verify, `require` →
  AcceptInvalidCerts, `disable` → Disabled). Single instance via
  `tauri-plugin-single-instance`; a second invocation focuses the window and
  opens a tab. The UI became a tab shell (one `Workspace` per tab, kept mounted;
  closing a tab disconnects it), and launches are *pulled* from an outbox on
  mount and on each `launch-pending` event so the first launch cannot race the
  webview's listener. Verified end to end with the built app: launched from a
  dir whose `.env` names the test Postgres, then invoked again from another dir
  with a URL — the second process exited immediately (exit 0), one process
  remained, and `pg_stat_activity` showed `sluice` sessions on both databases.
  **Scope decision (owner, 2026-11-06):** `--profile` is parsed now and resolved
  through a `ProfileLookup` trait whose current impl reports that saved profiles
  are not available yet; *resolving* it moves to T-036, which has the note.
  Only Postgres URLs connect; other schemes are refused by name.
