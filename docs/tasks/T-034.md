- **Notes**: New import_connection_url command: the URL crosses IPC inward as Secret<String>, is decomposed in the core, the password goes to the keychain under a new profile id, and the profile file gets host/port/user/database/tls only. The file has no URL field, so no string exists in which a password could survive; a failed file write rolls back the keychain entry. Closed a parser gap found on the way: libpq's `?password=` query parameter was kept as a plain-String param (printed by redacted()); it now lands in the Secret, and the userinfo password wins when both are given. Postgres schemes only in this build. save_session_as_profile (T-027/T-036) already covered the launched-URL path.
