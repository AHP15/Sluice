## T-051: Real query cancellation and per-profile statement timeout

- **Status**: done
- **Size**: M
- **Implements**: D-010

- **Acceptance**: Every query carries a cancel handle that stops the server-side query, an engine that cannot cancel cleanly declares that limit and falls back to dropping the connection, and a per-profile default statement timeout applies to all execution.

- **Notes**: Before this only the browse stream (T-049) could be stopped.
  **Cancel:** a `CancelSlot` per call; the lease records its connection's
  cancel token there, and `PgDriver::cancel` sends the protocol cancel
  request, which stops the query on the server (verified: the `pg_sleep` is
  gone from `pg_stat_activity`, the call returns `Cancelled` in well under 3s,
  and the single pooled connection is usable after). A slot cancelled before
  its query starts refuses to start it. A cancelled call's lease is marked
  dirty so release runs ROLLBACK + DISCARD ALL. **Fallback (D-010):** the app
  runs each cancellable call as a task (`execution::run`); `cancel_query`
  sends the cancel and, if the call has not finished after `CANCEL_GRACE`
  (3s), aborts it — dropping the lease, which closes its connection rather than
  returning it to the pool (T-039). The SQL Server driver will plug in here per
  D-030. **Timeout:** per-profile `statement_timeout_secs` on `ProfileMeta`
  (unset → default 300s, `0` → none; launched sessions get the default) is
  sent as a **startup option**, so the server enforces it on every statement
  and `DISCARD ALL` resets *to* it rather than clearing it (verified live). A
  client watchdog at timeout + grace backs it up for servers or proxies that
  drop startup options (transaction-mode PgBouncer does). SQLSTATE 57014 is
  split into `Timeout` vs `Cancelled` by message. The browse stream's deadline
  now comes from the session timeout instead of the fixed constant. UI: Run
  becomes Stop while a script runs. **Value to confirm:** D-010 records no
  default number; 300s was chosen to match T-049's stream deadline.
  Navigator and value fetch take no query id yet (fast catalog reads);
  they still get the server-side timeout.
