- **Notes**: At connect, one query loads every type with a default btree or hash opclass. Comparability is then resolved per column from tokio_postgres's Type kind tree: domains to their base type, enums via anyenum, arrays, ranges and multiranges via their element, composites only if every field is comparable. The static allowlist remains only as the fallback when the probe fails. Verified live: jsonb, numeric, uuid, citext, enum, domain and int4[] are protected, json and point are not, an unchanged edit over all of them commits, and the type-fidelity corpus passes with TEST_PG_URL set. float8 is now comparable: it has `=` and arrives over the binary protocol, so its original round-trips exactly; the T-058 live assertion was updated. Opt-in rendered form: EditRequest.compare_rendered adds `(col)::text IS NOT DISTINCT FROM $n::text` for non-comparable columns whose value as read is the server's own text (Text/Opaque), and PlannedStatement.concurrency_rendered reports it. Reduced protection now appears only per statement in the preview, with the opt-in toggle there; the grid's pending-bar banner and the dead unprotectedColumns helper are removed. Known limit: the probe is once per connection, so a type created after connect reads as not comparable until reconnect (under-protects, never over-claims).
