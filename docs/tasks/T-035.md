- **Notes**: Caps: 10,000 entries, 32 MiB total statement text, 64 KiB per statement (head kept, flagged truncated, not replayable), all enforced in the insert transaction. One-click purge deletes everything, checkpoints the WAL and VACUUMs, so the deleted text does not linger in free pages; deleting a profile purges its entries. Per-profile `history = "on"|"off"` in the profile file and IPC ProfileMeta; unset falls back to Guardrails (off when production-flagged, and launched/ephemeral sessions are off). The core's session guardrails decide recording, not the UI. Recording is best-effort and silent: history failure never fails a query and is never logged, because the only thing worth logging would be the statement. sluice-state has no logger dependency, and a test forbids logging, print and panic calls in the history store. Known gap: a launched session saved as a profile records under the new profile id while the History panel filters by the session-id prefix (the launch id), so its entries show under 'all profiles' until reconnect.
